| ID      | Requirement                                                | Acceptance / validation criterion                                                                                                                                                                                              | Priority                | Status |
| ------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- | ------ |
| **R1**  | **Problem is precisely defined**                           | Report states exactly what is predicted, at what point in time, and for what social-media domain.                                                                                                                              | MUST                    | PASS   |
| **R2**  | **Trend/surge has an operational definition**              | A deterministic rule converts observations into trend/surge vs non-trend labels; parameters and rationale are documented.                                                                                                      | MUST                    | PASS   |
| **R3**  | **Prediction horizon is explicit**                         | Observation window and future target window are clearly separated.                                                                                                                                                             | MUST                    | PASS   |
| **R4**  | **Target domain is bounded**                               | Platform, community/domain and unit of analysis are explicitly specified.                                                                                                                                                      | MUST                    | PASS   |
| **R5**  | **End-user/problem justification exists**                  | Identified users, their decision problem, and why earlier detection could help them are evidenced and connected to requirements.                                                                                               | MUST                    | PASS   |
| **R6**  | **Project objectives are measurable**                      | Each major objective can be mapped to an implementation output and evaluation result.                                                                                                                                          | MUST                    | PASS    |
| **R7**  | **Dataset provenance is documented**                       | Source, collection method, period, fields, filtering and resulting dataset size are reproducible/documented.                                                                                                                   | MUST                    | PASS   |
| **R8**  | **Raw → modelling dataset transformation is reproducible** | Pipeline can regenerate the modelling data from the project's intended input without undocumented manual transformations.                                                                                                      | MUST                    | PASS   |
| **R9**  | **Data quality is assessed**                               | Missing values, duplicates, malformed records, temporal coverage and relevant anomalies are examined and handled/documented.                                                                                                   | MUST                    | PASS   |
| **R10** | **Class distribution is analysed**                         | Number/proportion of surge and non-surge observations is reported and implications of imbalance are considered.                                                                                                                | MUST                    | PASS   |
| **R11** | **No target leakage**                                      | Every predictive feature can be calculated using only information available within the defined observation window.                                                                                                             | CRITICAL                | PASS   |
| **R12** | **Temporal ordering is respected**                         | Training/evaluation procedure does not allow future information to influence earlier predictions.                                                                                                                              | CRITICAL                | PASS   |
| **R13** | **Temporal/volume features implemented**                   | Features representing early activity dynamics—e.g. volume, lag, growth/change, short-term trend—are produced correctly.                                                                                                        | MUST                    | PASS   |
| **R14** | **Sentiment features implemented**                         | Sentiment is transformed into clearly defined modelling features and its temporal availability is leakage-safe.                                                                                                                | MUST for current design | PASS   |
| **R15** | **Additional engagement/content features are justified**   | Any included feature has a rationale connected to trend emergence rather than being included merely because it exists.                                                                                                         | SHOULD                  | PASS   |
| **R16** | **Feature engineering is documented**                      | Formula/algorithm, window, transformation and intended interpretation of important engineered features are described.                                                                                                          | MUST                    | PASS   |
| **R17** | **Feature usefulness is investigated**                     | Analysis shows whether important feature groups actually contain useful predictive information.                                                                                                                                | SHOULD                  | PASS   |
| **R18** | **Baseline exists**                                        | A clearly defined baseline—currently Logistic Regression—is trained and evaluated under the same experimental conditions as the main model.                                                                                    | MUST                    | PASS   |
| **R19** | **Main predictive model exists**                           | At least one stronger model—currently Random Forest—is trained successfully and produces probabilities/classes for unseen observations.                                                                                        | MUST                    | PASS   |
| **R20** | **Model pipeline is reproducible**                         | Preprocessing, feature selection/transformation, training and prediction can be executed consistently.                                                                                                                         | MUST                    | PASS   |
| **R21** | **Model configuration is documented**                      | Important hyperparameters, random seeds and training decisions are recorded.                                                                                                                                                   | MUST                    | PASS   |
| **R22** | **Baseline and main model are fairly compared**            | Same target definition, feature availability, data split and evaluation protocol are used.                                                                                                                                     | CRITICAL                | PASS   |
| **R23** | **Evaluation metrics match the problem**                   | At minimum precision, recall and F1 are reported, consistent with the template; ROC-AUC/PR-AUC may supplement them where appropriate.                                                                                          | MUST                    | PASS   |
| **R24** | **Class imbalance is handled analytically**                | Accuracy is not used alone; imbalance effects and relevant mitigation/evaluation choices are explained.                                                                                                                        | MUST                    | PASS   |
| **R25** | **Prediction errors are analysed**                         | False positives and false negatives are examined rather than reporting aggregate scores only.                                                                                                                                  | SHOULD                  | PASS   |
| **R26** | **Robustness/generalisation is investigated**              | Appropriate temporal validation, multiple splits/windows, sensitivity analysis or another defensible robustness check is performed.                                                                                            | SHOULD                  | PASS   |
| **R27** | **Results answer the project question**                    | Evaluation establishes what evidence exists for/against predicting future surge emergence from early social-media signals.                                                                                                     | CRITICAL                | PASS   |
| **R28** | **Feature contribution is analysed**                       | Results identify which signals/features appear useful, unhelpful or unstable, with appropriate caution about interpretation.                                                                                                   | MUST for strong outcome | PASS   |
| **R29** | **Baseline comparison is interpreted**                     | Explain not merely which model scores higher, but what the difference implies about the modelling problem.                                                                                                                     | MUST                    | PASS   |
| **R30** | **Limitations are evidence-based**                         | Data, labels, sampling, sentiment, generalisation, temporal scope and modelling limitations relevant to actual experiments are discussed.                                                                                      | MUST                    | PASS   |
| **R31** | **Objectives are individually evaluated**                  | Conclusion/evaluation returns explicitly to each original objective and states achieved / partially achieved / not achieved with evidence.                                                                                     | CRITICAL                | PASS   |
| **R32** | **Original contribution is identifiable**                  | Report explicitly identifies what is specific/original about this implementation—e.g. early-surge framing, label construction, temporal feature engineering, experimental comparison—not unsupported claims of novel research. | SHOULD                  | PASS   |
| **R33** | **Pipeline architecture is documented visually**           | Clear diagram shows data → preprocessing → aggregation/features → labels → model → prediction/evaluation.                                                                                                                      | MUST                    | PASS   |
| **R34** | **Important data transformations are visualised**          | Suitable plots/tables show raw behaviour, constructed surge labels and/or engineered signals.                                                                                                                                  | MUST                    | PASS   |
| **R35** | **Model results are visualised clearly**                   | Tables/plots make baseline-vs-main performance and relevant errors understandable.                                                                                                                                             | MUST                    | PASS   |
| **R36** | **Implementation can run end-to-end**                      | Final clean execution completes from intended input through prediction/evaluation without manual repair.                                                                                                                       | CRITICAL                | PASS   |
| **R37** | **Repository is submission-ready**                         | Dependencies, configuration, execution instructions, paths, seeds and required data/resources are documented.                                                                                                                  | MUST                    | PASS   |
| **R38** | **Final run is reproducible**                              | A clean final execution produces results consistent with those reported.                                                                                                                                                       | CRITICAL                | PASS   |
| **R39** | **Report and code agree**                                  | Feature names, dataset counts, windows, model settings and reported metrics match the frozen implementation/results.                                                                                                           | CRITICAL                | PASS   |
| **R40** | **No stale experimental claims remain**                    | Old metrics, abandoned designs, obsolete figures and prototype-only statements have been removed or clearly identified as historical.                                                                                          | MUST                    | PASS   |
| **R41** | **Literature supports the design**                         | At least the expected 4–6 previous works are discussed, while stronger work goes beyond that and critically relates literature to project choices.                                                                             | MUST                    | PASS   |
| **R42** | **All referenced work is properly cited**                  | All external work is cited consistently in ACM style, as explicitly required for full citation marks.                                                                                                                          | MUST                    | PASS   |
| **R43** | **Evaluation is broader than metric reporting**            | Evaluation covers major project issues and critically analyses results relative to objectives—the rubric explicitly separates these criteria.                                                                                  | CRITICAL                | PASS   |
| **R44** | **Demo proves the product works**                          | Demo shows representative input/data, execution or pipeline behaviour, outputs/predictions and evaluation rather than only slides explaining the idea.                                                                         | MUST                    |        |
