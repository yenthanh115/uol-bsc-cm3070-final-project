# R18 — Baseline exists

**Requirement:** Baseline exists
**Acceptance / validation criterion:** A clearly defined baseline—currently Logistic
Regression—is trained and evaluated under the same experimental conditions as the main model.
**Priority:** MUST

**Verdict: PASS**

Logistic Regression is explicitly designated as the interpretable baseline, is implemented and
trained by the same code path as the main models (Random Forest and XGBoost), and is evaluated
under identical experimental conditions — same features, same target, same temporal CV splits,
same seed, same held-out test set, same metric suite, and the same threshold-selection routine.
The report presents LR side-by-side with the main models in every results table. Both the
"clearly defined baseline" and "same experimental conditions" clauses of the criterion are met.

---

## Evidence from the codebase (`src/`)

### 1. Logistic Regression is a defined, first-class model — `training.py`

A dedicated factory builds the LR baseline with an explicit configuration (Elastic Net via the
`saga` solver, `class_weight='balanced'`):

```python
def _make_lr(params, random_seed):
    return LogisticRegression(
        C=params["C"], l1_ratio=params["l1_ratio"],
        solver="saga", class_weight="balanced",
        random_state=random_seed, max_iter=5000,
    )
```

and `_get_lr_param_grid()` defines its search space (grid size 10), parallel to the RF and XGB
grids.

### 2. Trained under the SAME conditions as the main models — `training.py` (`train_all_models`)

All three models are trained in one function from the **same inputs and the same procedure**;
LR is not handled specially:

```python
# Same training matrix / target for every model
X_train_full = train_df[FEATURE_COLUMNS].values.astype(np.float64)
y_train_full = train_df["surge_label"].values.astype(np.int64)

# Same temporal CV folds / splits for every model
folds = create_temporal_folds(train_df, n_folds=N_FOLDS)
splits = get_expanding_window_splits(folds)
_verify_temporal_ordering(train_df, folds, splits)

models["logistic_regression"] = _train_single_model(
    "logistic_regression", _get_lr_param_grid(),
    X_train_full, y_train_full, splits, random_seed, _make_lr,
)
models["random_forest"] = _train_single_model(
    "random_forest", _get_rf_param_grid(),
    X_train_full, y_train_full, splits, random_seed, _make_rf,
)
models["xgboost"] = _train_single_model(
    "xgboost", _get_xgb_param_grid(random_seed, imbalance_ratio=imbalance_ratio),
    X_train_full, y_train_full, splits, random_seed, _make_xgb,
)
```

Because LR, RF and XGB all pass through `_train_single_model` with the *same* `X_train_full`,
`y_train_full`, `splits`, and `random_seed`, they share:

- **Same feature availability** — identical `FEATURE_COLUMNS` (the 11 backward-only features).
- **Same target definition** — identical `surge_label`.
- **Same data split** — the same train partition and expanding-window CV folds, with the same
  chronological-ordering check.
- **Same per-fold preprocessing** — `_train_single_model` fits a fresh `StandardScaler` on each
  training fold for every model (per [@lst:grid-search]).
- **Same seed** — one `config.random_seed` passed to all three.

### 3. Evaluated under the SAME protocol — `run_training.py`, `evaluation.py`

`run_training.py` scores every model, LR included, on the same held-out test set with the same
metric functions (accuracy, precision, recall, F1, AUC-ROC) at both the default 0.5 threshold
and a validation-tuned threshold, and applies the same `find_optimal_threshold` routine to each.
LR is therefore evaluated identically to RF/XGB, and the same McNemar's/bootstrap machinery in
`evaluation.py` compares them pairwise. This is exactly the "same experimental conditions"
R18 requires.

## Evidence from the report (`final-report-v0.0.2.md`)

- **Baseline explicitly designated:** [@tbl:model-families] labels Logistic Regression the
  "Interpretable linear baseline (Elastic Net, L1+L2)", and [@sec:modelling-review] argues LR
  is "the appropriate baseline" against which tree ensembles are the "improved models".
- **Trained successfully:** the results report LR metrics on both datasets — e.g. WSB LR
  AUC-ROC 0.707 [0.684–0.729] and pennystocks LR 0.680 [0.588–0.778] ([@tbl:perf-default]),
  plus tuned-threshold metrics ([@tbl:perf-tuned]).
- **Same experimental conditions:** the Results preamble states all metrics are on the same
  chronologically held-out test partition; [@tbl:model-families]/[@sec:temporal-validation]
  describe the single expanding-window CV protocol applied to all models; [@lst:grid-search]
  documents the shared per-fold scaler isolation.
- **Fairly compared:** LR appears in the same tables as RF and XGB ([@tbl:perf-default],
  [@tbl:perf-tuned]), the single-feature baseline table ([@tbl:baselines]), the McNemar's
  significance tests ([@tbl:mcnemar]), and cross-dataset transfer ([@tbl:transfer]) — always
  under the same conditions.
- **Consistency:** the report's Logistic Regression / Elastic Net / `class_weight='balanced'`
  description matches `_make_lr` in the code, and the grid in [@tbl:hyperparams] matches
  `_get_lr_param_grid()`.

(The deeper interpretation of the baseline-vs-main gap is R29's concern; here it is cited only
to confirm the baseline is trained, evaluated, and compared under matched conditions.)
