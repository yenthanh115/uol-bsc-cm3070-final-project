# R38 — Final run is reproducible

**Requirement (CRITICAL):** A clean final execution produces results consistent with those reported.

**Verdict: PASS**

## What reproducibility requires here

Two things must hold: (1) the pipeline is deterministic (fixed seed → same result), and (2) the numbers in the report trace to persisted run artefacts produced by that deterministic pipeline. Both are verified below against code and on-disk evidence.

## Code evidence — determinism machinery

- `src/surge_pipeline/config.py`: `PipelineConfig.random_seed = 42` (default), serialisable to/from JSON (`to_json`/`save_json`/`load_json`) for an audit trail.
- `src/surge_pipeline/pipeline.py` (2 sites): seeds are set at run start —
  `random.seed(config.random_seed)` and `np.random.seed(config.random_seed)` — with a log line "Random seeds set to %d for deterministic execution."
- `src/surge_pipeline/training.py`: every estimator is constructed with `random_state=random_seed` (`_make_lr`, `_make_rf`, `_make_xgb`).
- `src/surge_pipeline/evaluation.py`: permutation importance uses `random_state=random_seed`; single-feature baselines use fixed `random_state=42`.
- Report §"Code Organisation": a fixed global seed (default 42) is set across Python's `random`, NumPy, and all scikit-learn estimators.

## On-disk evidence — reported numbers trace to persisted runs

`output/experiment_log.jsonl` is an append-only record; each line carries `run_id`, `git_sha`, the full `config` (including `seed: 42`), output paths, and a metrics `summary`. The reported headline results all match logged runs at seed 42:
