# R36 — Implementation can run end-to-end

**Requirement:** Final clean execution completes from intended input through prediction/evaluation without manual repair.
**Priority:** CRITICAL
**Assessed:** 2026-09-05 (verified by an actual clean end-to-end run)
**Verdict:** **PASS**

R36 is a CRITICAL requirement that cannot be satisfied by static evidence alone: it
demands that a *clean execution completes from the intended input through
prediction/evaluation without manual repair*. This assessment therefore ran the pipeline
end-to-end from the raw input CSV, in the project's own virtual environment, into a fresh
output directory, and confirmed it completed with no manual intervention and produced the
expected artefacts. The `r/pennystocks` dataset was used for the live run because it is the
smaller of the two shipped datasets (~40 MB vs ~232 MB) and completes in ~2 minutes total;
its full-run figures also reproduce the report closely, giving a strong correctness signal
(see §4).

---

## 1. Intended input and entry points are well defined ✔

- Intended input: raw Reddit submission CSVs under `input/raw/` — both present on disk:
  `r_pennystocks_submissions_reddit.csv` (~39.7 MB) and
  `r_wallstreetbets_submissions_reddit.csv` (232,426,316 bytes, matching the R7 fingerprint).
- The package (`surge-pipeline`) is installed in the project `.venv` (editable), and
  `import surge_pipeline` resolves to `src/surge_pipeline`. Runtime deps import cleanly
  (`sklearn`, `xgboost`, `vaderSentiment`, `pandas`).
- Entry points (`pyproject.toml [project.scripts]`, `@tbl:cli-entry-points`):
  `surge-label` → `run_labeling.py` (stages 1–5, load→window→sentiment→label→features),
  `surge-train` → `run_training.py` (stages 5–6, train + full evaluation).
  These chain the raw input through to prediction/evaluation.

## 2. Stage 1 — labelling ran clean from the raw CSV ✔

Command (from `src/`, project venv):

```
python run_labeling.py --file-path ..\input\raw\r_pennystocks_submissions_reddit.csv \
    --output-dir ..\output\<tmp>\processed --random-seed 42
```

Completed with `DONE`, no errors, no manual repair. Stage log (abridged):

- Load: 54,785 logical records → ticker extraction → **80,212 exploded record–ticker pairs**.
- Windowing: per-ticker 24 h counts, 55,385 (69.0%) excluded (sparse/boundary forward window).
- Sentiment: VADER over 24,827 included records (the slow stage, ~69 s, as the report notes).
- Labelling + threshold sweep: wrote `labelled_dataset.csv`, `pipeline_summary.json`,
  `threshold_sensitivity.csv`, `pipeline_config.json`, `latest_outputs.json`.
- Class distribution (all included): **698 surge / 24,129 no-surge = 24,827 usable** — exactly
  the report's `r/pennystocks` usable-record count (`@tbl:dataset-characteristics`). Total
  runtime 71.3 s.

## 3. Stage 2 — training + evaluation ran clean on the produced dataset ✔

Command:

```
python run_training.py --data-path ..\output\<tmp>\processed\<...>_labelled_dataset.csv \
    --output-dir ..\output\<tmp>\evaluation --models-dir ..\output\<tmp>\models --seed 42 --no-figures
```

Completed with `DONE`, no errors, total 56.9 s. It consumed the freshly labelled dataset
(all 11 feature columns present), trained all three models, ran the full evaluation
(McNemar, single-feature baselines, 1,000-resample bootstrap CIs, threshold tuning,
permutation + built-in importances, success tiers, final summary), and wrote artefacts:

- `output/<tmp>/models/{logistic_regression,random_forest,xgboost}_phase2_42_<ts>.joblib` + `latest_models.json`
- `output/<tmp>/evaluation/<ts>_{evaluation_metrics,feature_importance,final_summary,threshold_tuning}.json` + `latest_outputs.json`

Final summary: best model **random_forest, AUC 0.7527, tier "target", overall pass True**.

## Verdict

**R36: PASS.** A clean execution was performed live: `run_labeling.py` ingested the raw
`r/pennystocks` CSV and produced the labelled dataset and summaries, and `run_training.py`
consumed that dataset to train all three models and generate the full evaluation (metrics,
bootstrap CIs, McNemar tests, threshold tuning, feature importance, success-tier verdict,
final summary). Both stages completed with `DONE`, no errors, and no manual repair, writing
all expected model and evaluation artefacts. The run reproduces the report's `r/pennystocks`
figures across usable-record counts, per-model AUCs and CIs, single-feature baselines,
McNemar χ² values, and success tiers, confirming the implementation runs end-to-end from the
intended input through prediction and evaluation.

### Minor observations (not blocking)

- The live end-to-end verification used `r/pennystocks` (the ~40 MB dataset) for tractability
  (~2 minutes total). The `WSB` dataset (~232 MB, ~19 min per the report) exercises the same
  code path with the same entry points; it was not re-run here purely for time. The
  pennystocks reproduction is sufficient to establish the pipeline runs end-to-end without
  manual repair; a full `WSB` re-run is the natural extra step for the R38 (final-run
  reproducibility) assessment.
- The labelling → training hand-off is by explicit CSV path. `run_training.py` can also
  auto-discover the latest labelled dataset via `output/processed/latest_outputs.json` when
  no `--data-path` is given; when passing a path, it must be the CSV (not the manifest JSON).
  This is documented behaviour, not a defect.
