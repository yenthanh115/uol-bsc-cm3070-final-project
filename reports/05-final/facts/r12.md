# R12 — Temporal ordering is respected

**Requirement:** Training/evaluation procedure does not allow future information to influence earlier predictions.
**Priority:** CRITICAL
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R12 (CRITICAL) concerns the *procedure* rather than individual features (that is R11): the
train/test split, cross-validation, normalisation-statistic estimation, and threshold
selection must all respect chronological order, so no future observation can influence an
earlier prediction. Evidence below shows temporal ordering enforced at every stage of
`labelling.py` and `training.py`, backed by a hard runtime assertion and dedicated tests.

---

## 1. Chronological train/test split (not random)

`labelling._temporal_split()` splits by timestamp percentile, never by shuffling:

```python
epoch_seconds = pd.Series(to_epoch_seconds(df["created_utc"]), index=df.index)
split_ts = np.percentile(epoch_seconds.values, ratio * 100)      # ratio = 0.8
partitions = np.where(epoch_seconds.values <= split_ts, "train", "test")
```

- The earliest 80% (by time) become `train`; the final 20% become the held-out `test` set.
- Boundary ties go to **train** (`<= split_ts`) — the leakage-safe choice, since the boundary
  instant is never treated as future/test data.
- The report describes exactly this as "Level 1: Train/test split (80/20 by timestamp) …
  the final 20% form the held-out test set, evaluated exactly once" (§Temporal Validation).

This guarantees the test period is strictly later than the training period, so evaluation
measures genuine forecasting, not interpolation.

## 2. Normalisation statistics come from training only

Target labelling standardises with training-partition parameters exclusively, so no test-set
distribution information reaches earlier records:

```python
train_volume = df.loc[train_mask, "posting_volume_growth"] ...
mu_vol  = float(np.mean(train_volume));  sigma_vol  = float(np.std(train_volume, ddof=0))
# ... then z-score ALL records with the frozen training μ/σ
```

This is the label-side counterpart to R11's feature-side leakage prevention, and it is what
`test_labelling.py::TestZScoreNormalisation` verifies (test-set z-scores use training μ/σ, not
their own). Covered in detail under R9/R11; noted here because it is part of the temporal-ordering
guarantee.

## 3. Expanding-window CV: train strictly before validation

Within the training partition, cross-validation preserves order rather than using random k-fold:

```python
def create_temporal_folds(df, n_folds=4):
    sorted_indices = epoch_seconds.values.argsort()   # sort by time
    # slice into 4 sequential, chronological blocks

def get_expanding_window_splits(folds):
    for i in range(1, len(folds)):
        train_idx = np.concatenate(folds[:i])   # all preceding blocks
        val_idx = folds[i]                       # the next block
```

Each split trains on all blocks *before* the validation block, so every validation instance
occurs strictly after all its training instances — matching the report's `@fig:expanding-cv`
and "Level 2: Expanding-window CV within training (k=4)". The report's stated rationale cites
Bergmeir & Benítez [19] that random CV overestimates accuracy on time-dependent data.

## 4. A hard assertion makes a violation crash, not corrupt

`train_models()` calls `_verify_temporal_ordering()` immediately after building the splits:

```python
for i, (train_idx, val_idx) in enumerate(splits):
    max_train = epoch[train_idx].max()
    min_val   = epoch[val_idx].min()
    if max_train > min_val:
        raise ValueError(f"Temporal ordering violated in split {i}: ...")
```

This converts any future→past leakage into an immediate `ValueError` rather than a silent
result. The report documents this as making "lookahead leakage a crash rather than a silent
corruption" (`@lst:expanding-splits`). The report also records that an early timestamp-unit bug
motivated adding exactly this assertion (§Implementation Decisions).

## 5. Per-fold scaler isolation

Inside `_train_single_model()`, a fresh `StandardScaler` is fit on the *training fold only* and
then applied to the validation fold, so validation statistics never inform training:

```python
scaler = StandardScaler()
X_fold_train = scaler.fit_transform(X_train_full[train_idx])
X_fold_val   = scaler.transform(X_train_full[val_idx])
```

The final model refits a scaler on the whole training partition before scoring the test set —
still no test information enters fitting.

## 6. Operating threshold locked on validation, applied unchanged to test

The decision threshold is chosen on the last CV validation fold and applied to the test set
without modification (`train_models` selects `optimal_threshold` via `find_optimal_threshold`
on `val_y_true/val_y_prob`; `run_training.py` applies it to test predictions). The test set is
evaluated once. This prevents the test outcome from influencing the operating point — a subtle
temporal-ordering / contamination guard the report states as "applied unchanged to the test
set, so no test information informs the operating point" (§Evaluation Pipeline).

## 7. Cross-dataset transfer preserves ordering

`run_cross_validation.py` loads a model trained on one community and scores it on the other's
data without retraining, so the transfer experiment cannot leak either — it only ever applies a
frozen model forward.

## Tests enforcing R12

`src/tests/test_training.py::TestTemporalOrdering`:

- `test_folds_are_chronologically_ordered` — asserts `max(ts in fold i) <= min(ts in fold i+1)`
  for every consecutive fold pair.
- `test_cv_splits_respect_temporal_ordering` — asserts `max(train_ts) <= min(val_ts)` in every
  expanding-window split.
- `test_verify_temporal_ordering_raises_on_violation` — constructs folds that deliberately break
  ordering and asserts `_verify_temporal_ordering` raises `ValueError("Temporal ordering
  violated")`, proving the guard actually fires.

`TestExpandingWindowSplits` further confirms 4 folds → 3 splits and that the training set
expands each split. `test_labelling.py` covers the train-only normalisation. The report notes
these run automatically before every experiment (Testing Strategy, `@tbl:test-modules`).

## Procedure-level ordering summary

| Stage | Mechanism | Guarantee |
|-------|-----------|-----------|
| Train/test split | `_temporal_split` — 80th-percentile timestamp, ties→train | Test strictly later than train |
| Label normalisation | μ/σ from training partition only | No test distribution leaks into labels |
| Cross-validation | expanding-window, time-sorted folds | Validation strictly after training |
| Ordering guard | `_verify_temporal_ordering` assertion | Violation → crash, not silent leak |
| Scaling | per-fold `StandardScaler` fit on train fold only | No val/test stats in fitting |
| Threshold | tuned on validation fold, applied to test unchanged | Test never informs operating point |

Report and code agree: the report's Temporal Validation Design and pipeline-architecture
statement ("no stage may access future information relative to a record's observation time")
match the implementation at each stage.

---

## Verdict

**R12: PASS.** The training/evaluation procedure respects chronological ordering end-to-end: a
timestamp-based train/test split, training-only normalisation statistics, expanding-window
cross-validation where validation always follows training, a hard runtime assertion that turns
any ordering violation into an error, per-fold scaler isolation, and a validation-locked
threshold applied once to a strictly-later test set. Dedicated unit tests verify fold ordering,
split ordering, and that the guard raises on violation. No mechanism allows future information
to influence earlier predictions.

### Minor observations (not blocking)

- Because boundary ties go to train and Reddit timestamps are per-second, the realised train
  fraction can drift slightly from 0.8; this is the leakage-safe direction and does not affect
  ordering.
- R12 (procedure) and R11 (feature admissibility) are complementary; the train-only z-score
  evidence appears in both because it is simultaneously a label-normalisation and an
  ordering guarantee.
