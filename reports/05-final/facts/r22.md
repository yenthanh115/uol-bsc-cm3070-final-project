# R22 — Baseline and main model are fairly compared

**Requirement:** Same target definition, feature availability, data split and evaluation protocol are used.
**Priority:** CRITICAL
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R22 (CRITICAL) requires the baseline (Logistic Regression) and the main models (Random Forest,
XGBoost) to be compared on a level playing field: the same target, the same features, the same
train/test split, and the same evaluation protocol. The strongest evidence is that all three
models are trained inside a single `train_models()` call that constructs the target, feature
matrix, and splits **once** and hands the identical objects to every model — so a fair comparison
is guaranteed by construction, not by convention.

---

## 1. Same target definition

`train_models()` builds the label vector once from the shared labelled dataset and reuses it for
every model:

```python
y_train_full = train_df["surge_label"].values.astype(np.int64)
```

All three models receive this same `y_train_full`. The `surge_label` column is produced upstream
by the single labelling stage (`labelling.py`, composite z-score target) before any model is
trained, so LR, RF, and XGBoost all learn and are scored against the identical target with the
same $\tau$/$w_1$/$w_2$ configuration. Report `@sec:model-selection` frames all three as solving
"whether a ticker experiences a composite surge within the subsequent 24 hours."

## 2. Same feature availability

The feature matrix is built once from the shared `FEATURE_COLUMNS` and passed unchanged to each
model:

```python
X_train_full = train_df[FEATURE_COLUMNS].values.astype(np.float64)
```

There is no per-model feature selection or per-model column subset — `_train_single_model` is
called three times with the *same* `X_train_full`. Every model therefore sees the identical 11
features. Test-time prediction uses the same `FEATURE_COLUMNS` for all models
(`run_training.py` §4 / `training.predict`).

## 3. Same data split and CV folds

The temporal train/test split is fixed upstream in labelling (`partition` column), and
`train_models()` derives the CV folds/splits once and shares them:

```python
train_mask = (df["partition"] == "train") & (~df["excluded"].astype(bool))
...
folds  = create_temporal_folds(train_df, n_folds=N_FOLDS)
splits = get_expanding_window_splits(folds)
_verify_temporal_ordering(train_df, folds, splits)
# then: _train_single_model(..., X_train_full, y_train_full, splits, ...) for LR, RF, XGB
```

The same `splits` object is passed to all three `_train_single_model` calls, so every model is
tuned on identical expanding-window folds and retrained on the identical 80% training partition.
Test evaluation uses the same held-out `partition == "test"` mask for all models
(`run_training.py` §4). Per-fold `StandardScaler` isolation is applied identically inside
`_train_single_model` for every model, so no model gets a scaling advantage.

## 4. Same evaluation protocol

`run_training.py` scores all three models through one shared path on the same test partition:

- Identical metric computation loop (accuracy, precision, recall, F1, AUC-ROC, confusion matrix)
  over `predictions[name]`/`probabilities[name]` for each of LR/RF/XGB (§4).
- Identical statistical treatment: McNemar's pairwise tests (§5), the *same* single-feature and
  random baselines applied to every model (`evaluate_baselines`, §6), 1,000-resample bootstrap
  CIs (§7), and success-tier validation against the same AUC tiers (§8).
- Identical threshold-tuning rule: each model's operating threshold is selected on the *last
  validation fold* by F1-maximisation and applied unchanged to the test set (§7b) — same rule for
  every model, so none is tuned on the test set.

Report `@tbl:perf-default` presents LR/RF/XGB side by side with the same metric columns, CIs, and
tiers; `@tbl:mcnemar` compares them pairwise under a shared Bonferroni-corrected α — a like-for-like
comparison.

## 5. Same imbalance handling family (not a confound)

All three models address the identical class imbalance via cost-sensitive learning
(`class_weight="balanced"` for LR/RF; `scale_pos_weight` for XGBoost, from the same
training-partition ratio), rather than resampling one model's data differently. Report
`@sec:model-selection` / `@lst:model-factory` document this uniform strategy. This keeps the
comparison fair: the models differ in family, not in the data or the imbalance regime they face.

---

## Fairness-dimension map

| R22 dimension | Shared mechanism | Evidence |
|---------------|------------------|----------|
| Target definition | one `y_train_full = surge_label` | `train_models()`; upstream `labelling.py` |
| Feature availability | one `X_train_full = train_df[FEATURE_COLUMNS]` | `train_models()`; `predict`/run_training test path |
| Data split | shared `partition` mask + one `folds`/`splits` object | `create_temporal_folds` + `get_expanding_window_splits` reused for all three |
| Evaluation protocol | one metrics/McNemar/bootstrap/tier path on same test mask | `run_training.py` §4–8 |
| Threshold rule | validation-fold F1-max, applied unchanged to test | `run_training.py` §7b (same rule per model) |
| Imbalance handling | cost-sensitive for all three | `@lst:model-factory` |

Because the target, features, and splits are constructed once and passed by reference to every
model, divergence is structurally impossible without editing shared code.

---

## Verdict

**R22: PASS.** The baseline (LR) and main models (RF, XGBoost) are compared under identical
conditions: the same `surge_label` target, the same 11-feature `FEATURE_COLUMNS` matrix, the same
chronological train/test split and expanding-window CV folds, and the same evaluation protocol
(metrics, McNemar's tests, bootstrap CIs, success tiers, and a shared validation-fold threshold
rule). These are constructed once in `train_models()` and reused across all three models, so the
comparison is fair by construction. Report tables present the three models like-for-like, matching
the code.

### Minor observations (not blocking)

- Hyperparameter *grids* differ per model family (LR 10, RF 36, XGB ≤50; `@tbl:hyperparams`),
  which is expected and appropriate — R22 concerns equal data/target/split/protocol, not identical
  hyperparameters, and each model is tuned by the same CV procedure on the same folds.
- The backward-compatible `train_logistic_regression()` helper rebuilds the same matrices/splits
  the same way; the primary `train_models()` path used for the reported comparison shares them
  across all three models.
