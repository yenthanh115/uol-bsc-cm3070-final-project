# X2 — Train/test contamination through preprocessing

**Severity:** FATAL
**Failure mode:** Train/test contamination through preprocessing (scalers, imputers, feature
selection, resampling fit on the whole dataset rather than training data only).
**Why dangerous:** Apparently excellent test results become invalid.
**Final validation:** Fit scalers, imputers, feature selection, resampling etc. on training
data only.
**Assessed:** 2026-09-05
**Status:** **PASS**

X2 is FATAL, so it was checked directly against the code, not the report prose. Every fitted
preprocessing transform in the pipeline is fit on **training data only** and merely *applied*
to validation/test data. There is no imputer or resampler that computes cross-split statistics,
and the one normalisation that spans all records (the surge-label z-scores) is fit on the
training partition alone.

---

## 1. Feature scaling (`StandardScaler`) — fit on train only ✔

`StandardScaler` is the only fitted preprocessing transform in the modelling path. All three
fit sites fit on training data and transform val/test:

**Inner CV loop** (`training.py`, per fold):

```python
scaler = StandardScaler()
X_fold_train = scaler.fit_transform(X_train_full[train_idx])  # fit on TRAIN fold
X_fold_val   = scaler.transform(X_train_full[val_idx])        # transform VAL fold
```

**Final model** (`training.py`, after CV):

```python
final_scaler = StandardScaler()
X_train_scaled = final_scaler.fit_transform(X_train_full)     # fit on full TRAIN partition only
final_model.fit(X_train_scaled, y_train_full)
...
X_val_last = final_scaler.transform(X_train_full[last_val_idx])  # threshold tuning uses train-fitted scaler
```

The fitted scaler is stored on the returned `TrainedModel(..., scaler=final_scaler, ...)`.

**Test-set scoring** (`run_training.py`):

```python
X_scaled = tm.scaler.transform(X_test)   # train-fitted scaler, TRANSFORM only — never fit on test
y_pred   = tm.model.predict(X_scaled)
y_prob   = tm.model.predict_proba(X_scaled)[:, 1]
```

So the test set is standardised with statistics learned from training data only. The same
train-fitted scaler is reused for feature-importance permutation (`compute_feature_importance(scaler=tm.scaler, ...)`).

**Single-feature baselines** (`evaluation.py`) follow the identical discipline:

```python
scaler = StandardScaler()
X_train_scaled = scaler.fit_transform(X_train_f)   # fit on train
X_test_scaled  = scaler.transform(X_test_f)        # transform test
```

## 2. Target-label normalisation (z-scores) — fit on train only ✔

The composite surge target standardises volume growth and sentiment shift. The μ/σ are computed
**exclusively from the training partition** and then applied to all records (`labelling.apply_labelling`):

```python
train_volume = df.loc[train_mask, "posting_volume_growth"]...   # TRAIN mask only
mu_vol  = float(np.mean(train_volume));  sigma_vol  = float(np.std(train_volume,  ddof=0))
mu_sent = float(np.mean(train_sentiment)); sigma_sent = float(np.std(train_sentiment, ddof=0))
z_volume    = (all_volume    - mu_vol)  / sigma_vol      # applied to ALL records
z_sentiment = (all_sentiment - mu_sent) / sigma_sent
```

This is the highest-risk cross-split statistic in the pipeline, and it is train-only. It is
directly unit-tested in `test_labelling.py` (`test_test_set_uses_training_stats_not_own`), which
asserts test-set z-scores use the training mean/sd, not their own.

## 3. Imputation — no cross-split statistics ✔

The only `fillna` calls fill **text** nulls with a constant empty string, or numeric token
counts with a constant 0 — all row-local, none computed from data:

- `loader.py`: `df["selftext"].fillna("")`, `df["title"].fillna("")` (constant "").
- `features.py`: `titles/selftexts.fillna("")`; `word_count`/`title_length` `.fillna(0)` (constant 0).
- `sentiment.py`: `df["title"].fillna("")`, `df["selftext"].fillna("")` (constant "").

No `SimpleImputer`/`Imputer` and no mean/median imputation exist anywhere, so there is no
imputer that could be fit across the split. (The `.mean()` calls in `loader.py`/`sentiment.py`/
`features.py` are log-line summary statistics, not values fed back into features.)

## 4. Resampling / class imbalance — no leakage-prone resampler ✔

There is **no SMOTE or oversampling** in the pipeline (grep for `SMOTE`/`resample` returns only
the bootstrap-CI `n_resamples` argument, which resamples the *test set* post-hoc for confidence
intervals — an uncertainty estimate, not a preprocessing step feeding the model). Class
imbalance is handled *inside* the estimators via cost-sensitive learning
(`class_weight="balanced"` for LR/RF; `scale_pos_weight` for XGB), computed from the training
partition's class ratio. This is leakage-safe by construction and is also the design rationale
the report gives for rejecting SMOTE (`@sec:model-selection`).

## 5. Feature selection — none that could leak ✔

No supervised feature-selection transform (e.g. `SelectKBest`) is fit anywhere; the 11-feature
set is fixed a priori (`FEATURE_COLUMNS`). There is therefore no selection step that could be
fit on the full dataset.

## Status

**X2: PASS.** No train/test contamination through preprocessing. The only fitted transforms
(`StandardScaler` in the CV folds, the final model, and the single-feature baselines) are fit on
training data and applied to validation/test by `transform` only, with the train-fitted scaler
persisted on the model and reused for test scoring and feature importance. The one normalisation
that touches every record — the composite surge-label z-scores — uses training-partition μ/σ
exclusively and is unit-tested. There is no imputer, no SMOTE/oversampling, and no supervised
feature selection that could compute statistics across the split. The apparent test performance
is therefore not inflated by preprocessing leakage.

### Minor observations (not blocking)

- Class imbalance is handled by in-estimator cost-sensitive weighting rather than resampling, so
  X2's "resampling" clause is satisfied vacuously (no resampler to leak). This is a deliberate
  design choice documented in `@sec:model-selection`.
- The bootstrap procedure resamples the held-out **test** set to build confidence intervals; this
  is a post-hoc uncertainty estimate on already-computed predictions, not a preprocessing
  transform, and does not affect X2.
- X2 concerns preprocessing contamination specifically; related leakage vectors (feature/target
  timestamps, same-episode overlap across the split) are the subjects of X1/X6 and X3
  respectively and are out of scope for this item.
