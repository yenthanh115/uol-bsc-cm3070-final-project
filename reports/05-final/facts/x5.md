# X5 — Evaluation actually performed on training/validation data

**Severity: FATAL**
**Failure mode:** Evaluation actually performed on training/validation data (reported generalisation performance is meaningless).
**Final validation:** Confirm final reported metrics come from genuinely unseen held-out observations.

**Verdict: PASS** (all reported test metrics are computed on the disjoint chronological test partition, which is never used for fitting or hyperparameter/threshold selection)

## The train / test partitions are disjoint and defined once

`labelling._temporal_split()` assigns each record `partition ∈ {train, test}` by a single chronological cut on `created_utc` (`<= split_ts` → train, else test). This `partition` column is written to the labelled dataset and is the only source of the split downstream (see also x3.md).

## Fitting uses the TRAIN partition only (code)

`training.train_models()`:

```
train_mask = (df["partition"] == "train") & (~df["excluded"].astype(bool))
train_df = df.loc[train_mask].copy()
X_train_full = train_df[FEATURE_COLUMNS].values...
y_train_full = train_df["surge_label"].values...
```

- Hyperparameter search runs on expanding-window CV folds built **from `train_df` only** (`create_temporal_folds(train_df)` → `get_expanding_window_splits` → `_verify_temporal_ordering`).
- The winning configuration is retrained on the full train partition.
- The test partition is never referenced in `train_models`.

## Reported metrics use the TEST partition only (code)

`run_training.py` §4 "TEST SET EVALUATION":

```
test_mask = (df["partition"] == "test") & (~df["excluded"].astype(bool))
test_df = df.loc[test_mask]
X_test = test_df[FEATURE_COLUMNS].values...
y_test = test_df["surge_label"].values...
...
X_scaled = tm.scaler.transform(X_test)   # transform, NOT fit
y_pred = tm.model.predict(X_scaled)
y_prob = tm.model.predict_proba(X_scaled)[:, 1]
```

Every headline metric is computed against `y_test` from this partition:
- accuracy / precision / recall / F1 / ROC-AUC / confusion matrix (§4)
- McNemar's pairwise test — `mcnemar_pairwise_test(y_test, predictions)` (§5)
- Bootstrap 95% CIs — resamples of the test set (§7)

`train_mask` and `test_mask` are complementary on `partition`, so the evaluated rows are disjoint from the fitted rows.

## No test leakage via preprocessing or thresholds

- **Scaler**: fit on training folds / full train partition inside `train_models`; on test it is only `.transform`ed. No fit on test (consistent with X2).
- **Threshold**: `find_optimal_threshold` runs on the model's **last CV validation fold** (`tm.val_y_true`/`tm.val_y_prob`, drawn from within train), not on test. The tuned threshold is locked before test evaluation (report `@sec:temporal-validation`, `@sec:eval-pipeline`).
- **Normalisation stats** for the target (μ/σ) are training-only (`apply_labelling`).

## Report corroboration

- Results section: "All performance metrics are reported on the chronologically held-out test partition (the final 20% of data), which was isolated from training and threshold selection."
- `@sec:temporal-validation`: the held-out test set is "evaluated exactly once"; F1-optimised thresholds are "locked on validation folds and applied unchanged to the test set."
- `@sec:eval-pipeline`: "Threshold tuning maximises F1 on the last validation fold and is applied unchanged to the test set, so no test information informs the operating point."
- Persisted artefacts confirm the reported numbers are test-partition metrics with `support_positive`/`support_negative` matching the test partition (e.g. WSB eval JSON: 668 positives / 68,255 negatives = 68,923 test records; see r38.md/r39.md).
