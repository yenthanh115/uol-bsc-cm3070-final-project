# R26 — Robustness/generalisation is investigated

**Requirement:** Robustness/generalisation is investigated
**Acceptance / validation criterion:** Appropriate temporal validation, multiple splits/windows,
sensitivity analysis or another defensible robustness check is performed.
**Priority:** SHOULD

**Verdict: PASS**

The criterion asks for at least one defensible robustness/generalisation check; the project
performs several, each implemented in code and reported. These include temporal validation
(expanding-window CV plus a chronological holdout), two sensitivity sweeps (threshold τ and
sentiment weight w2), cross-dataset (cross-community) generalisation testing, uncertainty
quantification via 1,000-sample bootstrap confidence intervals, pairwise significance testing
(McNemar's), and a multi-seed stability check. Any one of these satisfies R26; together they
constitute a thorough investigation, so **R26 is comfortably met**.

---

## Evidence from the report (`final-report-v0.0.2.md`)

- **Temporal validation** ([@sec:temporal-validation]): an 80/20 chronological train/test split
  plus expanding-window CV (k=4), with every validation fold strictly after its training data —
  the rolling-origin scheme the literature recommends [18][19].
- **Sensitivity analysis** ([@sec:evaluation-framework], [@sec:sentiment-contribution]): two
  sweeps stress-test robustness — threshold sensitivity (τ ∈ {0.5,1.0,1.5,2.0,2.5}) and
  sentiment-weight sensitivity (w2 ∈ {0.0,0.25,0.50,0.75,1.00}, reported in
  [@tbl:weight-sensitivity]).
- **Cross-dataset transfer / generalisation** ([@sec:cross-community], [@tbl:transfer]): models
  trained on one community are evaluated on the other without retraining, quantifying
  generalisation (e.g. pennystocks→WSB AUC 0.871; WSB→pennystocks 0.684) and analysing the
  asymmetry.
- **Uncertainty quantification**: 1,000 bootstrap resamples give 95% CIs for every metric
  ([@tbl:perf-default]), and **McNemar's** tests establish pairwise significance
  ([@tbl:mcnemar]).
- **Multi-seed stability** (Implementation Status): five seeds (42,123,456,789,2024) give AUC
  0.734–0.753 (0.019 range), and determinism is verified across two dated runs.
- **Robustness limits acknowledged** ([@sec:temporal-stability]): the validation-to-test F1 gap
  is analysed as distribution shift, distinguishing ranking stability (AUC holds) from threshold
  miscalibration — an honest robustness discussion, not just a pass/fail number.

## Evidence from the codebase (`src/`)

### 1. Temporal validation — `training.py`

`create_temporal_folds` + `get_expanding_window_splits` build the expanding-window scheme, and
`_verify_temporal_ordering` raises if any split violates `max(train_ts) < min(val_ts)` — the
temporal-validation check is enforced, not just described.

### 2. Sensitivity sweeps — `labelling.py`, `pipeline.py`

`sweep_thresholds` evaluates the τ grid in one pass; `run_threshold_sweep` /
`_sweep_results_to_rows` produce the threshold-sensitivity table with a viability flag. The
sentiment-weight sweep is driven by re-running with different `weight_volume`/`weight_sentiment`
configs (the Phase 1 vs Phase 2 / w2 sweep).

### 3. Cross-dataset generalisation — `run_cross_validation.py`

A dedicated CLI ("Tests whether models trained on one subreddit … generalise to another")
loads models trained on one community, evaluates them on the other's data, writes a
`*_cross_validation.json`, and logs the run. This is the generalisation check behind
[@tbl:transfer].

### 4. Uncertainty & significance — `evaluation.py`

- `compute_bootstrap_ci` (default `n_resamples=1000`, `ci_level=0.95`, seeded) resamples the
  test set to produce 95% CIs for precision/recall/F1/AUC.
- `mcnemar_pairwise_test` computes pairwise significance between models.
- `test_evaluation_significance.py` verifies McNemar's χ² and bootstrap-CI coverage.

### 5. Multi-seed robustness — `run_training.py` / `config.py`

The seed is a single configurable field (`--seed` / `config.random_seed`) threaded through all
stochastic steps, enabling the five-seed stability run reported in Implementation Status; the
integration test `test_pipeline_integration.py::TestDeterminism` confirms run-to-run stability.
