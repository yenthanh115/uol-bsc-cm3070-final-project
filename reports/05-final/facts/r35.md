## What the criterion asks for

- **Baseline-vs-main performance understandable** — a reader can see how the Logistic Regression
  baseline compares to the Random Forest / XGBoost main models.
- **Relevant errors understandable** — false positives / false negatives (not just aggregate
  scores) are made legible.

Both must be delivered via **tables/plots**.

## How it was fixed

1. **Root cause.** `admin/experiment-plan.md` Step 4.4 generates figures per experiment into
   `output/figures/evaluation/{A2 (WSB), A1 (pennystocks), …}`. The report folder had been populated
   with the **A1 (pennystocks)** renders while the report narrative/tables are the **A2 (WSB)**
   headline results, so three of four figures contradicted the tables (e.g. the confusion matrix
   showed 0 TP under a caption asserting 157).

2. **Feature-importance figure enabled in the standalone generator.** `src/generate_figures.py`
   previously emitted only confusion/ROC/threshold figures; it now also computes permutation
   importance (`n_repeats=10`, `scoring=roc_auc`) and emits `13_feature_importance_comparison.png`,
   matching the figure set produced by `run_training.py`.

3. **Regenerated the WSB figure set from original source artefacts** (A2 models + A2 labelled
   dataset) into `output/figures/evaluation/20260905_A2/` — 11 figures, run confirmed the XGB tuned
   threshold 0.85 with 722 positive predictions (157 TP + 565 FP).

4. **Repointed all four report figure references** at that run and corrected the
   feature-importance caption to be WSB-specific (the cross-community contrast lives in
   `@tbl:feature-importance`). No figure files were copied into or moved within the report folder;
   the report references the original source files in place.
