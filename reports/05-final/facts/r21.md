# R21 — Model configuration is documented

**Requirement:** Model configuration is documented
**Acceptance / validation criterion:** Important hyperparameters, random seeds and training
decisions are recorded.
**Priority:** MUST

**Verdict: PASS**

The model configuration is documented on all three axes the criterion names. Hyperparameter
search spaces and the chosen settings are specified in the report and defined in code; the
random seed is a single documented config field threaded through every stochastic step and
logged with each run; and the training decisions (temporal grid search, per-fold scaler
isolation, class-imbalance handling, retrain-on-full-train, threshold selection) are described
in the report and implemented in the training module. Each run additionally persists its
resolved configuration, chosen thresholds, seed, and Git commit SHA to disk, so configurations
are not merely described but recorded per experiment.

## Evidence from the report (`final-report-v0.0.2.md`)

### Hyperparameters
- **[@tbl:hyperparams]** gives the full search space per model: LR (`C ∈ {0.01,0.1,1,10,100}`,
  `l1_ratio ∈ {0,1}`, grid 10); RF (`n_estimators ∈ {50,100,200}`, `max_depth ∈ {3,5,10,None}`,
  `min_samples_leaf ∈ {1,2,5}`, grid 36); XGBoost (`n_estimators`, `max_depth ∈ {3,5,7}`,
  `learning_rate ∈ {0.01,0.1,0.3}`, `scale_pos_weight ∈ {1, ratio/2, ratio}`, grid ≤50).
- **[@lst:model-factory]** documents the fixed per-model settings (LR `saga`/Elastic Net/
  `class_weight='balanced'`; RF `class_weight='balanced'`; XGB `scale_pos_weight`,
  `eval_metric='logloss'`), and **[@lst:imbalance-ratio]** documents how `scale_pos_weight` is
  derived from the training class ratio.
- Tuned decision thresholds per model are recorded in the results ([@tbl:perf-tuned], e.g. WSB
  XGB 0.85, RF 0.88; pennystocks XGB 0.16).

### Random seeds
- **Code Organisation** states "a fixed global seed (default 42) is systematically set across
  Python's native random module, NumPy, and all scikit-learn estimators."
- **Implementation Status** records the exact seeds used for the robustness check
  (42, 123, 456, 789, 2024) and the determinism verification (seed 42 reproduced identically).

### Training decisions
- **Model Training** and its listings document: expanding-window temporal grid search
  ([@lst:expanding-splits]), per-fold `StandardScaler` isolation ([@lst:grid-search]),
  selection of the highest mean-validation-AUC configuration, retraining the winner on the full
  80% training partition, cost-sensitive class-imbalance handling ([@lst:model-factory]), and
  locking F1-optimised thresholds on the validation fold ([@sec:temporal-validation],
  [@sec:eval-pipeline]).
- **Implementation Status** notes all runs are "trackable via logged configuration JSONs, Git
  commit SHAs, and timestamped output paths."

## Evidence from the codebase (`src/`)

### 1. Hyperparameter grids defined in code — `training.py`

`_get_lr_param_grid()`, `_get_rf_param_grid()`, and `_get_xgb_param_grid(random_seed, imbalance_ratio)`
define the exact search spaces from [@tbl:hyperparams]; the winning configuration is selected by
mean validation AUC and then retrained on the full training partition (per [@lst:grid-search]).
The fixed per-model settings live in the `_make_lr` / `_make_rf` / `_make_xgb` factories.

### 2. Random seed is a single documented, threaded field — `config.py`, `training.py`, `run_training.py`

`PipelineConfig.random_seed` (default 42, documented "All random operations use `random_seed`
for reproducibility") is passed into every model factory (`make_model_fn(params, random_seed)`),
into `train_all_models`, and into bootstrap CIs and permutation importance
(`random_seed=args.seed`) in `run_training.py`. One field controls all stochasticity.

### 3. Configuration is recorded per run — `run_training.py`, `experiment_log.py`, `pipeline.py`

- `run_training.py` writes a threshold JSON recording each model's chosen `optimal_threshold`
  and its validation-fold metrics, and calls `append_experiment(...)`.
- `experiment_log.append_experiment` writes one JSONL record per run capturing the `config`
  (weights, τ, sentiment model, seed, …), the **Git short SHA** (`get_git_sha()`), the output
  paths, and a metrics summary — an append-only audit trail.
- The labelling pipeline's `save_outputs` (in `pipeline.py`) additionally writes a standalone
  `*_pipeline_config.json` (`PipelineConfig.to_json`) and a summary JSON including the seed and
  all config fields.

So the important hyperparameters (chosen thresholds, weights), the seed, and the run context
are physically recorded to disk, not just printed.

### 4. Config serialisation is tested — `tests/`

`test_config.py` verifies JSON serialisation round-trips preserve all `PipelineConfig`
parameters ([@tbl:test-modules]), so the recorded configuration is faithful.

### Report ↔ code agreement

The grids in [@tbl:hyperparams] match `_get_*_param_grid`; the factory settings in
[@lst:model-factory] match `_make_lr/_make_rf/_make_xgb`; the seed-42 statement matches
`config.random_seed`. The documentation describes the configuration as implemented.
