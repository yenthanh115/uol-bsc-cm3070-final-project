## 1. Missing values — examined and handled

**Examined (EDA).** `data_quality()` in `03_deep_assessment.ipynb` computes per-column missing
percentage for every column and flags `high_risk_columns` (missing > 30%):

```python
missing = {c: round(float(df[c].isna().mean()) * 100, 2) for c in df.columns}
high_risk = [c for c, pct in missing.items() if pct > 30.0]
```

It emits a per-column `missing_pct` map and a **missingness bar figure**
(`plot_missingness`, with a 30% high-risk line). Result: both datasets show
`high_risk_columns` empty in `deep_assessment.csv` (no column exceeds the 30% threshold).

**Handled (pipeline).** `loader.py` fills missing text before extraction:
`df["selftext"].fillna("")` (also mapping `[deleted]`/`[removed]` to empty) and
`df["title"].fillna("")`; `features.py` and `sentiment.py` apply the same `fillna("")` guard.
Sentiment uses title-fallback when selftext is absent, so every record has a defined value.

**Documented (report).** §Data Representation ("moderation placeholders and nulls emptied";
title used when body absent) and §Data Loading Step 1. ✔

## 2. Duplicates — examined and documented

**Examined (EDA).** `data_quality()` reports `duplicate_rows = int(df.duplicated().sum())`,
and the assessment appends a risk string if any are found:
`if quality["duplicate_rows"] > 0: risks.append(...)`. Result in `deep_assessment.csv`:
`duplicate_rows = 0` for both datasets.

**Handled/documented (report).** §Data Loading Step 1 states each raw row maps to a unique
Reddit submission ID, so no deduplication is needed — consistent with the measured 0
duplicates. ✔

## 3. Malformed records — examined and handled

**Handled (pipeline).** `loader._read_csv()` converts low-level parse failures into clear,
actionable errors instead of opaque tracebacks:
- `pd.errors.EmptyDataError` → "Input CSV is empty"
- `pd.errors.ParserError` → "Input CSV is malformed and could not be parsed"
- `UnicodeDecodeError` → "Input CSV is not valid UTF-8 text"
- `FileNotFoundError` / `OSError` → explicit named-file errors.

Malformed timestamps are caught explicitly: `pd.to_datetime(..., errors="coerce")` followed by
a hard check that fails loudly if any value is unparseable
(`n_invalid = df["created_utc"].isna().sum(); if n_invalid > 0: raise ValueError(...)`),
preventing silent corruption of the chronological ordering the pipeline depends on.
Records that yield zero valid tickers after filtering are dropped (Step 4). ✔

## 4. Temporal coverage — examined and documented

**Examined (EDA).** `temporal_coverage()` computes the date range, total days, and counts
gaps longer than 7 days:

```python
gaps = int((dts.diff() > pd.Timedelta(days=7)).sum())
return {"date_range": (...), "total_days": ..., "gap_count": gaps}
```

Results (from `deep_assessment.csv` / `@tbl:eda-deep`):

| Dataset | Date range (sampled) | Total days | Gaps > 7 days |
|---------|----------------------|-----------|---------------|
| WSB | 2021-01-01 → 2021-01-28 | 27 | 0 |
| r/pennystocks | 2021-01-01 → 2021-12-31 | 364 | 0 |

A cross-dataset comparison figure plots days of coverage and temporal gaps side by side.

**Handled (pipeline).** Missing intra-ticker periods are not imputed; an absent interval simply
contributes a zero to a backward/forward count (report §Data Representation, "Missing periods").
Timestamps are normalised to UTC and sorted chronologically in `loader.py` Step 3.

**Documented (report).** `@tbl:eda-deep` reports "Coverage / gaps (>7 days): 364 days / 0" and
"27 days / 0". ✔

## 5. Relevant anomalies — examined and documented

**Examined (EDA).** The assessment aggregates a `risks` list flagging small samples, high-missing
columns, duplicate rows, temporal gaps, and low VADER/TextBlob sentiment agreement
(`sentiment_reliability`, reported as 0.723 "good" for pennystocks, 0.661 "moderate" for WSB).
The surge-viability sweep additionally confirms the label is neither degenerate nor trivially
separable before committing to the dataset.

**Documented (report).** §Data Selection Plan "Ethics and known limitations" and the Limitations
section document the inherited anomalies: **survivorship bias** (deleted posts absent), engagement
metrics **frozen at final values**, and findings tied to the **single 2021 period**. The
extreme class imbalance (sub-1% surge rate, ~102:1) is examined at length in §Dataset and Target
Analysis and the limitations. ✔

## Verdict

**R9: PASS.** Every dimension named in the acceptance criterion — missing values, duplicates,
malformed records, temporal coverage, and relevant anomalies — is examined by the EDA
deep-assessment tooling (`03_deep_assessment.ipynb`, persisted to `deep_assessment.csv` plus
figures) and either handled in the pipeline (`loader.py` cleaning, error handling, timestamp
validation) or documented in the report (`@tbl:eda-deep`, §Data Representation, limitations).
Measured results confirm clean data on both datasets (0 duplicates, 0 >7-day gaps, no
high-missing columns).

### Minor observations (not blocking)

- Quality figures (coverage, days, gaps: 2021-01-01→2021-01-28 for WSB) are from the capped
  100k-row EDA sample, so they differ from full-run figures — this boundary is explicitly noted
  in the report and does not affect the quality conclusions.
- Duplicate detection uses full-row `df.duplicated()`; because submission `id` is unique this is
  sufficient here, though an id-level check would be marginally stricter.
