# X10 — Performance is driven by a trivial proxy

**Severity:** CRITICAL
**Failure mode:** Performance is driven by a trivial proxy — the model technically predicts the
label but only because a feature is effectively a restatement of the label-generation variables,
so it does not demonstrate the intended research claim.
**Why dangerous:** Model technically predicts labels but does not demonstrate the intended
research claim.
**Final validation:** Compare important features with label-generation variables and inspect
feature importance / coefficient behaviour.
**Assessed:** 2026-09-05
**Status:** **PASS** (with a disclosed structural-correlation caveat)

X10 was checked by mapping the label-generation variables against the feature set and inspecting
the feature-importance behaviour. No label-generation *forward* variable appears as a feature,
the top feature is weak on its own (so it is not a restatement of the label), and the intended
research claim survives a control that removes the sentiment term from the target entirely. The
one genuine subtlety — that the top feature shares a term with the target's sentiment component —
is not leakage and is explicitly disclosed and bounded in the report.

---

## 1. Label-generation variables vs the feature set — no shared forward variable ✔

The target is `surge = 1` iff `w1·Z(posting_volume_growth) + w2·Z(sentiment_change) > τ`, where the
label-generation variables are:

- `posting_volume_growth = forward_count / max(backward_count,1) − 1` — uses the **forward** count.
- `sentiment_change = |mean_future_sentiment − sentiment_polarity|` — uses the **forward-window**
  mean sentiment.

The 11 features (`FEATURE_COLUMNS`) are checked against these:

| Label-gen variable | Appears as a feature? |
|---|---|
| `forward_count` | No |
| `posting_volume_growth` | No |
| `mean_future_sentiment` | No |
| `sentiment_change` | No |
| composite / `surge_label` | No |

None of the forward/target-side quantities is a feature. The features that are *related* to the
target are backward or concurrent: `ticker_post_rate_24h` = `backward_count` (the *denominator*
of the growth ratio, not the forward numerator), and `sentiment_score` = `sentiment_polarity`
(the *current* post's sentiment, the subtrahend in `sentiment_change`, not the forward mean). So
there is no feature that is a direct restatement of the label. (This is the X1 result;
X10 goes further and asks about *near*-proxies.)

## 2. The top feature is weak on its own — not a trivial proxy ✔

The decisive test for X10 is whether an "important" feature can reproduce the label by itself.
It cannot:

- `sentiment_score` is the **most important** feature by permutation importance (+0.146 to +0.203
  across models/datasets, `@tbl:feature-importance`), yet as a **standalone** single-feature
  classifier it achieves only **AUC 0.559–0.587** (`@sec:sentiment-signal`).
- The R36 live run corroborated this: the single-feature baseline `sentiment_score` scored
  AUC ≈ 0.559 on pennystocks, far from the ~0.75 multi-feature result.

If the model were riding a trivial proxy of the label, that proxy alone would score near-perfect
AUC. Instead sentiment is only weakly predictive alone and becomes important **in the context of
other features** (interaction with activity rate), which is a substantive finding, not a proxy
artefact. The report explains exactly this: "permutation importance measures contribution *in
context of other features* … accelerating volume combined with elevated emotional tone is a
stronger surge precursor than either alone."

## 3. The research claim survives removing the sentiment term from the target ✔

The volume half of the target (`posting_volume_growth`) is built from `forward_count`, which is
genuinely not a feature (features use `backward_count` only). The Phase 1 control isolates this:

- With sentiment removed from the target (`w2 = 0`, volume-only), XGBoost still reaches
  **AUC 0.710** on WSB (`@tbl:phase-comparison`).

So surges are predictable from backward-only signal even when the sentiment term — the locus of
the structural-correlation worry — is stripped from the label. The intended research claim
("surges can be forecast from backward-looking signals") does not depend on the near-proxy.

## 4. Multi-feature integration beats the best single feature ✔

The models add real value over any single signal (`@tbl:baselines`): +0.087 AUC over the best
single feature on WSB (0.805 → 0.892) and +0.162 on pennystocks (0.591 → 0.753). Performance is
therefore distributed across features, not concentrated in one proxy — reinforced by
`@sec:complexity-density` noting RF spreads Gini importance across six features on pennystocks.

## 5. The residual structural correlation is disclosed and bounded ✔

The one honest subtlety: `sentiment_score` (feature, current sentiment at `t`) and the target's
`sentiment_change` (uses `mean_future − current`) share the `sentiment_polarity` term. The report
flags this explicitly in the limitations: "`sentiment_score` dominates importance, but sentiment
change is part of the composite target. The feature uses *current* sentiment while the target
uses *forward-window* shift, **not leakage, but a circularity that likely inflates sentiment's
apparent importance**. Phase 1 provides a partial control: with `w2 = 0`, XGBoost still achieves
AUC 0.710." This is the correct treatment: it is timing-clean (X4/X6 confirm the feature is at
`t`, the target term is forward), it is acknowledged, and its influence is quantified rather than
hidden.

## Status

**X10: PASS.** Performance is not driven by a trivial proxy of the label. No label-generation
forward variable (`forward_count`, `posting_volume_growth`, `mean_future_sentiment`,
`sentiment_change`, composite) appears in the feature set; the most important feature
(`sentiment_score`) is only weakly predictive on its own (AUC ≈ 0.56–0.59), so it is not a
restatement of the target; the multi-feature models beat the best single feature by +0.087 to
+0.162 AUC; and the core claim holds even when the sentiment term is removed from the target
(Phase 1, AUC 0.710). The one near-proxy relationship (feature `sentiment_score` shares the
current-sentiment term with the target's forward sentiment shift) is timing-clean, explicitly
disclosed as a circularity that may inflate that feature's apparent importance, and partially
controlled by Phase 1 — which is the appropriate scientific treatment, not a hidden shortcut.

### Minor observations (not blocking)

- Because of the disclosed circularity, `sentiment_score`'s permutation-importance magnitude
  should be read as an upper bound on its genuine contribution; the volume-only Phase 1 result is
  the cleaner evidence of predictability and is reported. This is a nuance in *interpreting
  importances*, not a proxy-driven-performance failure.
- A stricter future check (e.g. a feature-only-vs-volume-only-target ablation reported per model)
  would further quantify the circularity; the existing Phase 1 vs Phase 2 comparison already
  provides the key control, so this is optional hardening rather than a gap.
