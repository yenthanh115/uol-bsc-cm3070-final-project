## Metric code uses standard library implementations

`run_training.py` §4 computes the reported metrics with scikit-learn's canonical functions on the held-out test set:

```
acc  = accuracy_score(y_test, y_pred)
prec = precision_score(y_test, y_pred, zero_division=0.0)
rec  = recall_score(y_test, y_pred, zero_division=0.0)
f1   = f1_score(y_test, y_pred, zero_division=0.0)
auc  = roc_auc_score(y_test, y_prob)          # guarded to 0.5 if one class present
cm   = confusion_matrix(y_test, y_pred, labels=[0, 1])
```

These are not hand-rolled formulas, so the risk is limited to (a) mis-wiring inputs or (b) a bespoke test/CI implementation. Both are checked below.

## Statistical tests are correctly implemented

- **McNemar** (`evaluation.mcnemar_pairwise_test`): builds discordant pair counts `b` (A right, B wrong) and `c` (A wrong, B right), computes the standard `χ² = (b−c)²/(b+c)`, uses an **exact binomial test** when the discordant count `< 25` and the χ² approximation otherwise, and applies **Bonferroni** correction (`α / n_comparisons`). This matches `@sec:statistical-validation` (Bonferroni-adjusted α = 0.017 for 3 comparisons) and is the textbook formulation.
- **Bootstrap CIs**: 1,000 test-set resamples per metric (report `@sec:eval-pipeline`), a standard percentile-bootstrap for uncertainty.
