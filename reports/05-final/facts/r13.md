# R13 — Temporal/volume features implemented

**Requirement:** Temporal/volume features implemented
**Acceptance / validation criterion:** Features representing early activity dynamics—e.g.
volume, lag, growth/change, short-term trend—are produced correctly.
**Priority:** MUST

**Verdict: PASS**

The pipeline implements a set of backward-looking temporal and volume/activity features that
cover every category the criterion names — volume, lag, growth/change and short-term trend —
and their correctness is verified by unit tests using analytically hand-computed values.
The features are defined in `features.py` (with the volume growth metric produced upstream in
`windowing.py`), documented in the report ([@tbl:feature-definitions], [@tbl:feature-detail]),
and shown empirically useful in the evaluation (feature importance, single-feature baselines).

Every category in the acceptance criterion is represented by at least one concrete feature.

## Evidence from the codebase (`src/`)

### 1. Volume feature — `ticker_post_rate_24h`

Backward 24-hour posting count per ticker, reused from the windowing stage (so it is
backward-only by construction):

```python
# Feature 5: ticker_post_rate_24h — reuse backward_count from windowing
df = df.assign(ticker_post_rate_24h=df["backward_count"].values.copy())
```

`windowing.compute_windowed_counts` computes `backward_count` over `(t − 24h, t)` via
`np.searchsorted`, excluding the self-post.

### 2. Lag feature — `time_since_previous`

Hours since the most recent prior post for the same ticker; `-1` for a first occurrence:

```python
def _compute_time_since_previous(df, created_utc):
    result = np.full(n, -1.0, dtype=np.float64)
    for _ticker, group in df.groupby("ticker", sort=False):
        ...
        result[idx[1:]] = np.diff(times) / 3600.0   # gap to immediately preceding post
    return result
```

### 3. Growth/change — `posting_volume_growth` (target) and change captured via acceleration

Volume growth is the forward/backward ratio computed in `windowing.py`:

```python
posting_volume_growth = (forward_counts / np.maximum(backward_counts, 1)) - 1.0
```

(This is the growth signal that defines the surge target; backward *change* dynamics enter
the feature matrix through acceleration below.)

### 4. Short-term trend — `ticker_post_acceleration`

Ratio of the recent 12-hour count to the older 12-hour count, i.e. whether backward posting is
accelerating (>1) or decelerating (<1):

```python
recent_left  = np.searchsorted(times, times - _12H_SECONDS, side="right")
recent_right = np.searchsorted(times, times,                side="left")
count_recent = recent_right - recent_left

older_left   = np.searchsorted(times, times - _24H_SECONDS, side="right")
older_right  = np.searchsorted(times, times - _12H_SECONDS, side="right")
count_older  = older_right - older_left

acceleration = count_recent / np.maximum(count_older, 1)
```

### 5. Cyclic temporal features — `hour_of_day`, `day_of_week`

Extracted from the record's own creation time (creation-time-only, leakage-safe):

```python
created_utc = pd.to_datetime(df["created_utc"], utc=True)
df = df.assign(
    hour_of_day=created_utc.dt.hour.values,
    day_of_week=created_utc.dt.dayofweek.values,  # Monday=0
)
```

### 6. Produced correctly — enforced ordering + hand-computed tests

`compute_features` asserts chronological ordering before computing any backward-looking
feature, so incorrect (potentially leaky) values fail loudly:

```python
if np.any(np.diff(_epoch_check) < 0):
    raise ValueError("Input DataFrame must be sorted chronologically ... before feature engineering.")
```

`src/tests/test_features.py` verifies each temporal/volume feature against analytically
hand-computed values:

- **Volume:** `test_ticker_post_rate_uses_backward_count` — `ticker_post_rate_24h` equals the
  windowing `backward_count`.
- **Lag:** `TestTimeSincePrevious` — first occurrence is `-1`; a sequence at 0/12h gives 12.0;
  a 4-post sequence gives the expected successive gaps (3.0, 7.0, 5.0); it looks strictly
  backward (`test_time_since_previous_is_backward_only`: 0h/6h/12h → −1, 6.0, 6.0).
- **Short-term trend:** `TestTickerPostAcceleration` — zero-denominator case returns the
  numerator (`0.0` then `1.0`), and a populated case returns the expected `0.5` ratio.
- **Cyclic temporal:** `test_temporal_features_use_creation_time_only` — `hour_of_day` and
  `day_of_week` match `created_utc` exactly.
- **Determinism / shape:** two runs are bit-identical; the matrix is exactly the 11
  `FEATURE_COLUMNS`; no NaNs for non-excluded records.

The report notes these tests pass with zero errors ([@tbl:test-modules], `test_features.py`).
