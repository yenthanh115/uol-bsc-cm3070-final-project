## Minor documentation defects (do not block PASS; worth fixing)

These are inaccuracies in `README.md` that do not prevent regeneration but should be corrected for a
clean submission:

1. **Sentiment backend mislabelled.** `README.md` describes sentiment as *TextBlob* and instructs
   `python -m textblob.download_corpora`. The pipeline default (and the report) is **VADER**
   (`vaderSentiment`), which needs no corpus download and ran without that step.
   `RUNNING_AND_TESTING.md` correctly lists both and notes VADER. TextBlob is only an optional
   sentiment backend / EDA reliability check.
2. **EDA entry point drift.** `README.md` references `src/eda/eda_pipeline.py` (`python -m
   eda.eda_pipeline`), but the shipped EDA is three notebooks under `src/eda/` (per the report). The
   EDA is a separate screening aid and is not on the results-regeneration path, so this does not
   affect X16.
3. `README.md`'s project-structure listing predates the multi-dataset/multi-model final state
   (mentions only pennystocks, LR-only training, TextBlob). `RUNNING_AND_TESTING.md` is current;
   a marker following it will succeed.
