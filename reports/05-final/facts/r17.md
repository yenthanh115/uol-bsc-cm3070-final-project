# R17 — Feature usefulness is investigated

**Requirement:** Analysis shows whether important feature groups actually contain useful predictive information.
**Priority:** SHOULD
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R17 asks for *analysis* — not merely a feature list — establishing whether the important feature
groups carry genuine predictive signal. The project investigates this four independent ways
(permutation importance, single-feature baselines, a sentiment standalone-vs-in-context
analysis, and target-composition ablations), each produced by re-runnable code and reported with
appropriate caution. That is comfortably beyond the SHOULD bar.

---

## 1. Permutation importance — which features carry signal in context

**Code.** `evaluation.compute_feature_importance()` runs sklearn `permutation_importance`
(`scoring="roc_auc"`, `n_repeats=10`, seeded) on the held-out test set for each tree model;
`compute_builtin_importance()` additionally extracts gain-based importances for the tree models.
`run_training.py` §7c calls both, prints ranked tables, and writes
`<prefix>_feature_importance.json`; `plot_feature_importance()` renders the figure.

**Report analysis.** § Feature Importance (`@tbl:feature-importance`, `@fig:feature-importance`)
reports the top-5 permutation importances per model/dataset and interprets group behaviour:
`sentiment_score` dominates everywhere (+0.113 to +0.203); activity features
(`ticker_post_rate_24h`, `time_since_previous`) fill the next ranks; and the ordering *shifts*
between the dense (WSB) and sparse (pennystocks) communities — "`time_since_previous` rises to
second … reflecting reliance on temporal gaps when volume is low." This is precisely a
group-usefulness analysis.

## 2. Single-feature baselines — does each feature beat chance, and does combining help?

**Code.** `evaluation.evaluate_baselines()` trains a **one-feature Logistic Regression per
feature** on train and scores AUC on test, records every `single_feature_aucs`, identifies the
best single feature, and computes `improvement_over_best_single_feature` for each model.

**Report analysis.** § Statistical Validation / `@tbl:baselines`: best single feature on WSB is
`word_count` (AUC 0.805) and on pennystocks `hour_of_day` (0.591); the full multi-feature models
add +0.087 and +0.162 AUC respectively. This directly tests whether the feature groups "actually
contain useful predictive information" and whether integrating them beats the strongest lone
signal — and quantifies it.

## 3. Sentiment: useful alone vs useful in combination

The report explicitly probes an apparent contradiction rather than taking importance at face
value. § The Sentiment Signal (`@sec:sentiment-signal`): as a *standalone* feature
`sentiment_score` achieves only modest AUC (0.559–0.587), yet it *dominates permutation
importance*. The report resolves this: permutation importance measures contribution *in context*
— "accelerating volume combined with elevated emotional tone is a stronger surge precursor than
either signal alone." This is a genuine usefulness investigation (a feature group can be weak in
isolation but valuable jointly), reported with the right caution.

## 4. Target-composition ablations — sentiment and interaction terms

- **Phase 1 vs Phase 2 / weight sweep** (`@tbl:phase-comparison`, `@tbl:weight-sensitivity`):
  compares a volume-only target ($w_2=0$) against the composite, isolating sentiment's
  contribution (+0.182 AUC on WSB), and notes the confound (base-rate shift) rather than
  overclaiming — "part of the gain stems from altered task difficulty."
- **Interaction-term ablation** (§ Feature Engineering (Implementation)): "An ablation study
  confirmed a consistent +1.4pp AUC lift from including these terms" — a direct test of whether
  the interaction features earn their place.

## Cautious interpretation (required by R17's spirit)

The analysis repeatedly flags interpretation caveats: the standalone-vs-context discrepancy is
explained rather than ignored; the sentiment gain is partly attributed to task-difficulty change;
and the limitations section records a **structural correlation** between `sentiment_score` and the
composite target ("current sentiment vs forward-window shift … a circularity that likely inflates
sentiment's apparent importance," `@sec:sentiment-signal`, Limitations), with Phase 1 offered as a
partial control. This is the "appropriate caution" R28-style analysis that R17 anticipates.

## Verdict

**R17: PASS.** The project does not merely list features — it investigates their usefulness with
permutation importance (in-context contribution), single-feature Logistic Regression baselines
(standalone signal and the gain from combining), a sentiment standalone-vs-context analysis, and
target-composition ablations (Phase 1/2, weight sweep, interaction-term ablation). Findings are
reported per feature group, contrasted across the dense and sparse communities, and qualified with
explicit caution (including the sentiment/target circularity). The supporting numbers are produced
by re-runnable code (`evaluate_baselines`, `compute_feature_importance`,
`compute_builtin_importance`) and persisted as artefacts.

### Minor observations (not blocking)

- `@tbl:baselines` and the baseline text describe "eleven univariate Logistic Regression models"
  in `@sec:evaluation-framework` while `evaluate_baselines` docstring says "9 features"; the code
  iterates the full `FEATURE_COLUMNS` (11), so the run covers all features — a stale docstring
  comment, an R39 detail, not an R17 gap.
- R17 is a SHOULD; the depth here (four complementary analyses plus caution) exceeds it.
