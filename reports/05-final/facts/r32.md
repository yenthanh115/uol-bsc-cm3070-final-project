# R32 — Original contribution is identifiable

**Requirement:** Report explicitly identifies what is specific/original about this implementation—e.g. early-surge framing, label construction, temporal feature engineering, experimental comparison—not unsupported claims of novel research.
**Priority:** SHOULD
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R32 has two parts: (a) the report must *explicitly* state what is specific/original about
this implementation, and (b) those statements must be grounded claims (tied to the actual
design, code and results), **not** unsupported claims of novel research. Both parts hold.
The report contains a dedicated `## Originality and Contribution` section that names three
contributions and, critically, qualifies them as *incremental* combinations of established
techniques rather than novel research — and each of the three is traceable to concrete
code and saved artefacts.

---

## 1. The report explicitly identifies its original contribution ✔

Originality is stated in three places, consistently:

- **Aim (`@sec:aim`):** "The **contributions** are a leakage-free forecasting methodology,
  a composite volume-and-sentiment surge metric, and evidence that data density constrains
  performance more than model complexity."
- **Abstract:** "The main contribution is therefore a temporally valid ranking and
  screening framework…".
- **Conclusion → `## Originality and Contribution`:** a dedicated section enumerating the
  same three contributions, each in its own paragraph:
  1. *"a **leakage-free methodology applied where neglected**"* — cites the literature gap
     (`@sec:methodological-weaknesses`, `@tbl:temporal-practices`) and states the framework
     is reusable for any timestamped prediction problem.
  2. *"a **composite surge metric** integrating normalised volume growth with sentiment
     change, fully parameterised by threshold and weights"* — points to the Phase 1 vs
     Phase 2 experiment (`@tbl:phase-comparison`).
  3. *"**empirical evidence that data density is the binding constraint**"* — points to the
     dataset gap (0.753 vs 0.892) and asymmetric transfer (0.871 / 0.684).

These map directly onto the requirement's suggested categories: **label construction**
(composite surge metric), **temporal feature engineering / methodology** (leakage-free
pipeline), and **experimental comparison** (density/complexity, cross-community transfer).

## 2. The claims are grounded, not unsupported novelty claims ✔

The requirement's key qualifier is "*not unsupported claims of novel research*." The report
is explicitly careful here:

- The Originality section closes with: *"Direct comparison with published baselines is not
  possible… These are incremental contributions, combining established techniques into a
  coherent framework for a problem prior work has not directly addressed, with each claim
  grounded in quantified evidence."*
- It frames the temporal-validation contribution as *applying established principles*
  [18][19] where prior work neglected them — i.e. a rigour/application claim, not a claim to
  have invented temporal CV.

Each of the three contributions is backed by frozen code and artefacts:

| Contribution | Report anchor | Code / artefact evidence |
|---|---|---|
| Leakage-free methodology | `@sec:methodological-weaknesses`, `@sec:temporal-validation`, `@tbl:temporal-practices` | `labelling.py` (train-only μ/σ z-scores), `training.py` `_verify_temporal_ordering` hard-asserts `max(train) < min(val)`; `test_labelling.py` / `test_features.py` enforce no-future-leakage |
| Composite surge metric | `@sec:surge-definition`, `@tbl:phase-comparison`, `@tbl:weight-sensitivity` | `labelling.py`: `composite = (w1 * z_volume) + (w2 * z_sentiment)`, configurable `weight_volume`/`weight_sentiment`, `sweep_thresholds()`; phase/weight-sweep evaluation artefacts under `output/evaluation/` |
| Data density is binding constraint | `@sec:complexity-density`, `@sec:cross-community`, `@tbl:transfer` | `run_cross_validation.py` + `output/evaluation/*_cross_validation.json` (WSB↔pennystocks transfer); AUC gap reported in `@tbl:perf-default` |

## 3. Novelty is appropriately bounded ✔

The report does **not** overclaim. It positions the work against the four research gaps
(`@sec:research-gap`, `@tbl:research-gaps`) — onset vs eventual-outcome target, signal
integration, domain specificity, temporal validity — and repeatedly frames its own
contribution as incremental and evidence-grounded. This is exactly the posture R32 asks for:
specific and identifiable, without inflated claims of novel research.

## Verdict

**R32: PASS.** The report explicitly and consistently identifies its original contribution
(a leakage-free forecasting methodology, a composite volume-and-sentiment surge metric, and
empirical evidence that data density is the binding constraint) in the abstract, aim, and a
dedicated `## Originality and Contribution` section. These map onto the requirement's
categories of label construction, temporal feature engineering/methodology, and experimental
comparison. Crucially, the claims are grounded — each is traceable to frozen code
(`labelling.py`, `training.py`, `run_cross_validation.py`) and saved artefacts
(`output/evaluation/*_cross_validation.json`, phase/weight sweeps) — and the report
explicitly frames them as incremental combinations of established techniques rather than
unsupported claims of novel research.
