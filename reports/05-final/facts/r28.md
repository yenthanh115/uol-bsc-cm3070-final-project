# R28 — Feature contribution is analysed

**Requirement:** Results identify which signals/features appear useful, unhelpful or unstable, with appropriate caution about interpretation.
**Priority:** MUST for strong outcome
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R28 asks the *results* to identify which features are useful, which are unhelpful, and which are
unstable — and to interpret this cautiously. The evaluation does all three: a dedicated
Feature Importance results subsection quantifies per-feature contribution, the critical analysis
separates genuinely useful signals from weak/negligible ones and flags instability across
communities, and multiple caveats guard the interpretation. All figures are produced by the
seeded evaluation pipeline with saved artefacts.

---

## 1. Which features are useful

Report § Feature Importance (`@tbl:feature-importance`, `@fig:feature-importance`) reports
permutation importances (10 repeats, `scoring=roc_auc`) per model/dataset and identifies the
useful signals:

- **`sentiment_score` dominates everywhere** (+0.113 to +0.203 across all four model/dataset
  combinations) — the single most useful feature.
- **Activity features are the next tier:** `ticker_post_rate_24h` and `time_since_previous` fill
  ranks 2–3.
- The multi-feature models beat the best single feature (`@tbl:baselines`: +0.087 on WSB, +0.162
  on pennystocks), establishing that the combined feature set carries real predictive information,
  not just one dominant column.

## 2. Which features are unhelpful / weak

The results explicitly call out low-contribution features rather than only highlighting winners:

- **Interaction terms are near-useless on the dense community:** "Interaction terms remain
  negligible on WSB (≤+0.005)" — while `word_count_x_hour` reaches only +0.017 on pennystocks RF.
- `day_of_week` and `num_tickers` appear only at rank 5 with tiny importances (+0.002 to +0.006).
- The single-feature baselines (`@tbl:baselines`, and the saved `feature_importance.json` /
  final-summary artefacts) show several features barely beat chance alone (e.g. `hour_of_day`,
  `time_since_previous` ≈ 0.50), identifying them as weak in isolation.

## 3. Which features are unstable

The analysis identifies instability — features whose usefulness shifts by community:

- § Feature Importance: on WSB activity features fill ranks 2–3, but "on pennystocks
  `time_since_previous` rises to second (+0.086), reflecting reliance on temporal gaps when volume
  is low" — i.e. the feature ordering is not stable across datasets.
- § Cross-Community Transfer (`@sec:cross-community`): `word_count` alone reaches AUC 0.805 on WSB
  but only 0.573 on pennystocks — a strongly community-dependent (unstable) signal, and the report
  ties the asymmetric transfer directly to over-reliance on this unstable feature.

## 4. Appropriate caution about interpretation

R28 explicitly requires interpretive caution, and the report supplies it repeatedly:

- § The Sentiment Signal (`@sec:sentiment-signal`): resolves the apparent paradox that
  `sentiment_score` is weak *alone* (AUC 0.559–0.587) yet dominates *in-context* permutation
  importance — explaining that permutation importance measures contribution conditional on other
  features, so the headline ranking must not be read as standalone power.
- Limitations: flags a **structural correlation** between `sentiment_score` and the composite
  target ("a circularity that likely inflates sentiment's apparent importance"), with Phase 1
  ($w_2=0$, AUC 0.710) offered as a partial control — directly cautioning against over-reading the
  top feature.
- The permutation-importance figure caption and text note the density-dependent reordering rather
  than presenting a single universal ranking.

## Reproducible artefacts behind the results

The feature-contribution results are pipeline outputs, not ad-hoc:

- `evaluation.compute_feature_importance()` (permutation) and `compute_builtin_importance()`
  (gain-based) produce per-feature values; `evaluate_baselines()` produces single-feature AUCs.
- Saved artefacts confirm generation: `output/evaluation/*_feature_importance.json` (multiple
  runs) and the `feature_importance_comparison.png` figure used as `@fig:feature-importance`.

## Verdict

**R28: PASS.** The results identify useful signals (sentiment dominant; activity features next),
unhelpful ones (negligible interaction terms, near-chance single features), and unstable ones
(community-dependent `word_count` and shifting activity/temporal ranks), and interpret them with
appropriate caution (in-context vs standalone importance, and the acknowledged sentiment/target
circularity). The analysis is backed by seeded permutation-importance and single-feature baseline
artefacts. This satisfies the "MUST for strong outcome" bar.

### Minor observations (not blocking)

- R28 overlaps with R17 (feature usefulness investigated); R17 concerns whether usefulness is
  *investigated*, R28 concerns whether the *results* identify useful/unhelpful/unstable signals —
  both hold, drawing on the same permutation-importance and baseline machinery.
- Importance magnitudes vary slightly across the multiple saved runs (different τ/seed configs);
  the report's headline ranking (sentiment first, activity next, interactions negligible) is
  consistent across them.
