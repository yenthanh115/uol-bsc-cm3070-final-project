# X14 — Baseline comparison is not truly like-for-like

**Severity: CRITICAL**
**Failure mode:** Baseline comparison is not truly like-for-like (claim that RF/XGB improves on LR becomes unsupported).
**Final validation:** Same observations, split, target, evaluation protocol and preferably clearly documented feature configuration.

**Verdict: PASS** (LR baseline and RF/XGB main models share the identical data, split, target, feature matrix, and evaluation path; the only differences are the intended, documented estimator/hyperparameter choices)

## Same observations and split (code)

`training.train_models()` builds the training arrays **once** and passes the same arrays to every model:

```
train_mask = (df["partition"] == "train") & (~df["excluded"].astype(bool))
train_df   = df.loc[train_mask].copy()
X_train_full = train_df[FEATURE_COLUMNS].values...
y_train_full = train_df["surge_label"].values...
folds  = create_temporal_folds(train_df) ; splits = get_expanding_window_splits(folds)

models["logistic_regression"] = _train_single_model("logistic_regression", _get_lr_param_grid(), X_train_full, y_train_full, splits, seed, _make_lr)
models["random_forest"]       = _train_single_model("random_forest",       _get_rf_param_grid(), X_train_full, y_train_full, splits, seed, _make_rf)
models["xgboost"]             = _train_single_model("xgboost",             _get_xgb_param_grid(...), X_train_full, y_train_full, splits, seed, _make_xgb)
```

All three receive the **same** `X_train_full`, `y_train_full`, and expanding-window `splits`. Test evaluation (`run_training.py` §4, see x5.md) scores all three on the **same** `X_test`/`y_test` from `test_mask`.

## Same target

Every model trains on `y_train_full = train_df["surge_label"]` and is evaluated on the same `y_test = test_df["surge_label"]`. There is a single target column produced once by the labelling stage; the baseline and main models are not scored against different label definitions.

## Same feature configuration (documented)

All three models use the identical feature matrix `train_df[FEATURE_COLUMNS]` — the same 11 columns (see x1.md / R39). No model is given a different or expanded feature set. The per-model differences are exactly and only:
- the **estimator** (`_make_lr` / `_make_rf` / `_make_xgb`), and
- its **hyperparameter grid** and imbalance strategy (`class_weight='balanced'` for LR/RF; `scale_pos_weight` for XGB).

These are documented in the report: `@tbl:model-families` (roles), `@tbl:hyperparams` (grids), and `@lst:model-factory` (constructors). This satisfies the "clearly documented feature configuration" clause.

## Same evaluation protocol

The `run_training.py` evaluation loop applies an identical path to each model: `tm.scaler.transform(X_test)` → `predict` / `predict_proba` → the same sklearn metrics (`precision_score`, `recall_score`, `f1_score`, `roc_auc_score`, `confusion_matrix`). Pairwise significance uses `mcnemar_pairwise_test(y_test, predictions)` on the same `y_test`, and bootstrap CIs resample the same test set. So model differences are compared under one common protocol.

## Per-model scaler is not a fairness violation

Each model fits its own `StandardScaler` on the training folds/full-train partition and applies it at test. This is per-model but **equivalent** across models (same fit data, same transform), and is required so each estimator sees consistently scaled inputs; it does not advantage one model over another and does not alter observations/split/target.

## Report corroboration

- `@sec:model-selection` / `@tbl:model-families`: LR is the interpretable baseline; RF and XGB are the improved models, chosen to span the bagging/boosting contrast.
- Results `@tbl:perf-default` / `@tbl:baselines` / `@tbl:mcnemar`: all models reported on the same test partition with the same metrics; the RF/XGB-vs-LR gains are quantified with bootstrap CIs and McNemar significance — a like-for-like comparison. (Corroborates R22 = PASS.)

## Summary

| Like-for-like condition | Result |
|---|---|
| Same observations | Yes (one `X_train_full`/`X_test`) |
| Same train/test split | Yes (shared `partition`, shared CV `splits`) |
| Same target | Yes (single `surge_label`) |
| Same feature configuration | Yes (identical `FEATURE_COLUMNS`) |
| Same evaluation protocol | Yes (identical metric + significance path) |
| Only intended differences (estimator/hyperparameters) | Yes, and documented (`@tbl:model-families`, `@tbl:hyperparams`, `@lst:model-factory`) |

**X14 = PASS**
