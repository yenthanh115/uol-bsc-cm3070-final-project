# R23 — Evaluation metrics match the problem

**Requirement:** At minimum precision, recall and F1 are reported, consistent with the template; ROC-AUC/PR-AUC may supplement them where appropriate.
**Priority:** MUST
**Assessed:** 2026-09-05
**Verdict:** **PASS**

R23 has one mandatory clause — **precision, recall and F1 must be reported** — and one
optional clause — ROC-AUC/PR-AUC *may* supplement them. The mandatory metrics are
computed in code, persisted to artefacts, and reported for every model on both datasets;
ROC-AUC supplements them as the primary ranking metric. R23 therefore passes. A PR-AUC
report↔code discrepancy exists but is non-blocking for R23 (PR-AUC is explicitly optional
here) and is flagged for R39.

---

## 1. Mandatory metrics (precision, recall, F1) — computed in code ✔

`src/surge_pipeline/evaluation.py` imports and applies scikit-learn's
`precision_score`, `recall_score`, `f1_score` (and `roc_auc_score`,
`confusion_matrix`):

- `evaluate_model()` (legacy `TrainingResult`) and `evaluate_trained_model()`
  (multi-model `TrainedModel`) both compute:
  ```python
  prec = precision_score(y_true, y_pred, zero_division=0.0)
  rec  = recall_score(y_true, y_pred, zero_division=0.0)
  f1   = f1_score(y_true, y_pred, zero_division=0.0)
  auc  = roc_auc_score(y_true, y_prob)   # guarded for single-class partitions
  ```
  and pack them into an `EvaluationMetrics` record (precision, recall, f1, roc_auc,
  support_positive, support_negative, confusion_matrix).
- `find_optimal_threshold()` sweeps thresholds 0.01–0.99 and records precision, recall and
  F1 at **both** the tuned operating point and the default 0.5 threshold
  (`precision_at_threshold`/`recall_at_threshold`/`f1_at_threshold` and the
  `*_at_default` counterparts) — matching the report's two results tables.

The module docstring states its purpose directly: "Computes Precision, Recall, F1-score,
and ROC-AUC on the held-out test set."

## 2. Mandatory metrics — persisted to artefacts ✔

The metrics are not merely computed in memory; they are written to disk. Example
(`output/evaluation/2026-07-15_11-18_evaluation_metrics.json`, a pennystocks run with the
same 31 test surges the report cites):

| Model | precision | recall | f1 | roc_auc |
|-------|-----------|--------|-----|---------|
| logistic_regression | 0.0128 | 0.6452 | 0.0250 | 0.6801 |
| random_forest | 0.1250 | 0.1290 | 0.1270 | 0.7436 |
| xgboost | 0.0000 | 0.0000 | 0.0000 | 0.7368 |

Every model record carries `precision`, `recall`, `f1`, `roc_auc`, class support, and the
confusion matrix. `save_evaluation_results()` serialises these to
`output/evaluation/*_evaluation_metrics.json`.

## 3. Mandatory metrics — reported in the report ✔

- `@tbl:perf-default` ("Test-set performance at default classification threshold (0.5)")
  has explicit **Precision, Recall, F1** columns (plus AUC-ROC with 95% CIs and tier) for
  LR/RF/XGB on both WSB and pennystocks.
- `@tbl:perf-tuned` ("Metrics at validation-tuned thresholds") reports **Precision,
  Recall, F1** (and ΔF1) for all three models on both datasets.
- `@tbl:eval-metrics` (Design) names the four reported metrics and their roles: AUC-ROC
  (primary), Precision, Recall, F1.
- `@tbl:confusion` and `@fig:confusion-matrix` give TP/FP/FN/TN, from which precision and
  recall are directly recoverable, and `@sec:error-analysis` analyses those errors.

## 4. Optional supplement (ROC-AUC) — present and appropriate ✔

- ROC-AUC is the **primary** metric throughout (`@sec:model-selection`,
  `@tbl:success-tiers`, `@tbl:perf-default`), justified by the sub-1% surge rate that
  makes accuracy uninformative.
- This matches R23's allowance that "ROC-AUC/PR-AUC may supplement" the mandatory trio,
  and its use is well-motivated for a severely imbalanced ranking problem.

## 5. "Consistent with the template" — accuracy not used as the headline ✔

The report explicitly rejects accuracy as a headline metric ("With surge rates of 1–5%,
accuracy is uninformative, a naive 'no surge' predictor achieves 95–99%") and centres the
evaluation on precision/recall/F1 plus ROC-AUC. This is the metric set the template
expects for an imbalanced classification problem, so the reported metrics match the
problem.

## Verdict

**R23: PASS.** The mandatory metrics — precision, recall and F1 — are computed in
`evaluation.py` (at both default and validation-tuned thresholds), persisted to
`output/evaluation/*_evaluation_metrics.json`, and reported for all three models on both
datasets (`@tbl:perf-default`, `@tbl:perf-tuned`). ROC-AUC supplements them as the primary
metric, which is appropriate for the severely imbalanced target, and accuracy is
explicitly excluded as a headline. This satisfies R23's "at minimum precision, recall and
F1 … ROC-AUC/PR-AUC may supplement" criterion.

### Non-blocking observation (belongs to R39, not R23)

- **PR-AUC is claimed but not computed.** The report states PR-AUC is a reported secondary
  metric (`@sec:model-selection`: "Precision, Recall, $F_1$, and PR-AUC are reported as
  secondary metrics"; `@sec:eval-pipeline`: "precision, recall, $F_1$, and PR-AUC at both
  the default 0.5 threshold and the validation-tuned threshold") and cites a value
  ("PR-AUC of approximately 0.14"). However, a source search
  (`pr_auc|average_precision|precision_recall_curve`) found **no PR-AUC computation** in
  `src/`, and `EvaluationMetrics` has no PR-AUC field. This does not affect R23, because
  R23 lists PR-AUC as optional ("may supplement") and the mandatory trio is fully present.
  It is a report/code agreement issue that should be raised under **R39** — either
  implement PR-AUC (e.g. `average_precision_score`) and populate the ~0.14 figure from an
  artefact, or soften the report's claim that PR-AUC is a computed/reported metric to
  reflect that it is an interpretive estimate.
