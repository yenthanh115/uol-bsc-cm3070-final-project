# R8 — Raw → modelling dataset transformation is reproducible

**Requirement:** Raw → modelling dataset transformation is reproducible
**Acceptance / validation criterion:** Pipeline can regenerate the modelling data from the
project's intended input without undocumented manual transformations.
**Priority:** MUST

**Verdict: PASS**

The transformation from the raw Reddit submissions CSV to the modelling dataset (labelled
records plus the 11-feature design matrix) is implemented as a single, deterministic,
config-driven code path — `load → window → sentiment → label → features` — orchestrated by
`run_pipeline()` and invoked through the `run_labeling.py` CLI. Every step is in code, no
step requires manual editing of intermediate files, randomness is seeded from the config, and
the raw input is fingerprinted (SHA-256 + row/column/timestamp metadata) so a third party can
confirm they started from identical source data. An end-to-end integration test asserts that
two runs with the same config produce identical results, and the report documents the same
chain stage-by-stage. Together these satisfy "regenerate the modelling data from the intended
input without undocumented manual transformations."

---

## Evidence from the codebase (`src/`)

### 1. A single orchestrator chains every stage — `surge_pipeline/pipeline.py`

`run_pipeline()` executes the whole raw→modelling transformation in order, with no manual
step in between:

```python
def run_pipeline(config: PipelineConfig) -> dict:
    # Seed randomness for determinism (R7-AC1, AC2)
    random.seed(config.random_seed)
    np.random.seed(config.random_seed)
    ...
    df, stage_counts, stage_durations = _run_through_sentiment(config, ...)  # load → window → sentiment
    labelling_result = apply_labelling(df, config)                           # label
    sweep_results = sweep_thresholds(df, config)                             # threshold sweep
```

and `_run_through_sentiment()` runs the first three stages:

```python
df = load_data(config)                    # Stage 1
df = compute_windowed_counts(df, config)  # Stage 2
df = compute_sentiment(df, config)        # Stage 3
```

The modelling design matrix is produced in `save_outputs()` by the same code path:

```python
labelled_df = compute_features(results["labelled_df"])   # Stage 5: 11 features
labelled_df.to_csv(labelled_path, index=False)
```

This is exactly the pipeline the report describes in [@tbl:pipeline-stages]
(Data Loading → Temporal Windowing → Sentiment → Target Labelling → Feature Engineering).

### 2. The raw input is the project's intended input — `loader.py`

`load_data()` ingests the raw CSV named by `config.file_path`, and the CLI defaults that path
to the project's intended input directory:

```python
# run_labeling.py
_DEFAULT_INPUT_DIR = str(PROJECT_ROOT / "input" / "raw")
```

which matches the raw datasets in the repository (`input/raw/r_wallstreetbets_submissions_reddit.csv`,
`input/raw/r_pennystocks_submissions_reddit.csv`). The loader performs every raw→clean
transformation in code — text cleaning, dual-regex ticker extraction with a 297-term stopword
lexicon, timestamp normalisation (epoch or ISO string), chronological sort, drop-if-no-ticker,
and `pandas.explode()` into one row per record–ticker pair — matching the four steps in the
report's "Data Loading and Preprocessing" section. No manual pre-editing of the CSV is
required; malformed input raises explicit errors rather than needing hand-repair.

### 3. Determinism is enforced from a single seed — `config.py`, `pipeline.py`

All tuneable parameters live in one serialisable `PipelineConfig` dataclass (`random_seed`
default 42), and `run_pipeline()` seeds both `random` and `numpy` from it before any
processing. The report corroborates this ("a fixed global seed (default 42) is systematically
set"). Because the transformation is a pure function of `(raw CSV, config)`, re-running
regenerates the same modelling data.

### 4. Reproducibility is verified by test — `tests/test_pipeline_integration.py`

The end-to-end integration test runs the full pipeline twice on the same config and asserts
identical output:

```python
class TestDeterminism:
    def test_deterministic_labelled_df(self, synthetic_config):
        r1 = run_pipeline(synthetic_config)
        r2 = run_pipeline(synthetic_config)
        # numeric columns compared for equality across the two runs
    def test_deterministic_stage_counts(self, synthetic_config):
        r1 = run_pipeline(synthetic_config)
        r2 = run_pipeline(synthetic_config)
        assert r1["stage_counts"] == r2["stage_counts"]
```

It also asserts the regenerated modelling frame carries the required columns
(`ticker`, `created_utc`, `forward_count`, `backward_count`, surge/label columns) and that
`save_outputs()` writes the labelled CSV, summary JSON and config JSON to disk.

### 5. Source-data integrity is fingerprinted — `loader.compute_dataset_fingerprint()`

Each real run computes a SHA-256 of the raw file plus structural metadata (row count, sorted
column names, timestamp min/max), attaches it to the DataFrame, and `save_outputs()` writes it
into the pipeline summary JSON:

```python
fingerprint = {
    "sha256": ..., "file_size_bytes": ..., "columns": ...,
    "num_rows": ..., "timestamp_column": ..., "timestamp_min": ..., "timestamp_max": ...,
}
```

This lets a third party confirm the regeneration started from byte-identical input.

### 6. Every run is logged for audit — `run_labeling.py` + `experiment_log.py`

The CLI appends an experiment-log entry per run recording the resolved config (threshold,
weights, sentiment model, split ratio, seed, surge method), the output paths, and a run
summary, and `save_outputs()` additionally writes a standalone `*_pipeline_config.json` and a
`latest_outputs.json` manifest. The transformation is therefore not only reproducible but
self-documenting.
