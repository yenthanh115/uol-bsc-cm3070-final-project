## A3 Implementation: Backward-only windowing

Implemented `surge_method: "backward_only"` in the pipeline. Instead of requiring
future posts to compute surge (forward/backward ratio), the new method defines surge
as backward_count exceeding the ticker's historical expanding mean.

- Test surges: **108** (vs 31 in A1 forward_growth) — 3.5x more
- Test surge rate: 3.30% (vs 0.95%)
- Class imbalance: 29:1 (vs 105:1) — much healthier

### Analysis

**A3 is a clear downgrade from A1.**

1. **XGBoost collapsed** — predicted only 1 positive out of 108 (recall=0.9%).
   With a weaker signal, boosting became ultra-conservative and defaults to
   all-negative predictions. Same failure mode as pre-A1 when data was scarce.

2. **AUC dropped ~0.05 across all models** — the backward-only surge definition
   produces a weaker separating signal. Features don't discriminate backward
   surges as cleanly as forward surges.

3. **Why the signal is weaker:** Forward_growth labels posts that *precede*
   heightened activity (leading indicator). Backward_only labels posts that
   appear *during* heightened activity (lagging indicator). The prediction
   features (word_count, hour_of_day, text length, etc.) are better correlated
   with the "will this blow up next?" question than "is this already blowing up?"

4. **Random Forest maintained recall** (91.7%) but at the cost of much worse
   precision (17.6% vs 38.1%) — it compensated for the weaker signal by
   predicting more positives, generating 465 false positives.

### Decision

**Revert to `surge_method: "forward_growth"` as default.** The A1 configuration
remains the best performer (XGBoost AUC=0.986, F1=0.785).

The forward-looking dependency for *labelling* is theoretically acceptable — labels
are ground truth derived from observed outcomes. Only *features* must be strictly
backward-only to prevent leakage (which they already are). The A3 approach solves
a theoretical concern that doesn't actually harm model validity.

### Next steps

- Consider B1 (drop weak features) or B3 (tune τ) as next improvement
- The backward_only code remains available as an option for future experiments
