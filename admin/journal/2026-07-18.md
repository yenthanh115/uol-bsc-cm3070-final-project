## Fix: `threshold_sensitivity.csv` missing date prefix

### Problem

The file `output/processed/threshold_sensitivity.csv` lacked the `YYYY-MM-DD_HH-MM_` prefix that all other pipeline outputs use. Same issue for `pipeline_summary.json` and `pipeline_config.json`.

### Root cause

Two issues:

1. **Legacy files** — The unprefixed files were artifacts from early pipeline runs before the date-prefix convention was introduced. The current `save_outputs()` in `pipeline.py` always writes prefixed files, but the old ones were never cleaned up.

2. **Hardcoded paths in `eda_pipeline.py`** — The EDA pipeline used hardcoded unprefixed filenames as defaults:
   ```python
   LABELLED_DATASET_PATH = ... / "labelled_dataset.csv"
   THRESHOLD_SENSITIVITY_PATH = ... / "threshold_sensitivity.csv"
   ```
   Other downstream scripts (`run_training.py`, `generate_figures.py`) had already been updated to resolve paths from `latest_outputs.json`, but the EDA pipeline was missed.

3. **Stale `latest_outputs.json`** — The manifest referenced `2026-07-16_15-45_*` files that didn't exist on disk (labelling ran from wrong CWD during Phase 1 experiment). The actual latest files were `2026-07-16_06-23_*`.

### Fix applied

1. **`src/eda/eda_pipeline.py`** — Replaced hardcoded paths with `_resolve_latest_path()` function that:
   - Reads `latest_outputs.json` manifest
   - Tries resolving relative to processed dir, then project root, then filename only
   - Falls back to globbing `*_{fallback_filename}` and picking the most recent match
   - Only uses the unprefixed name as a last resort

2. **`output/processed/latest_outputs.json`** — Corrected manifest to point to `2026-07-16_06-23_*` files that actually exist.

3. **Deleted stale files:**
   - `output/processed/threshold_sensitivity.csv`
   - `output/processed/pipeline_summary.json`
   - `output/processed/pipeline_config.json`
