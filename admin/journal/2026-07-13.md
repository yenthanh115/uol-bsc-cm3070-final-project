## B2 Experiment: Add interaction features

### Rationale

Tree models can discover interactions implicitly through multi-level splits, but providing explicit interaction terms can help by:
1. Reducing required tree depth to capture the signal
2. Providing the interaction directly to linear models (LR)
3. Offering a stronger signal for hyperparameter search to lock onto

### Implementation

Added 2 interaction features to `FEATURE_COLUMNS` in `src/surge_pipeline/features.py`:

1. **`word_count_x_hour`** = `word_count × hour_of_day`
   - Hypothesis: long posts at peak trading hours (market open, after-hours) carry more signal about coordinated activity
   
2. **`accel_x_time_since_prev`** = `ticker_post_acceleration × time_since_previous`
   - Hypothesis: rapid posting acceleration after a period of silence is a stronger surge indicator than either feature alone
   - Edge case: first-occurrence records (`time_since_previous = -1`) are zeroed to avoid spurious negative products

No relabelling needed — interaction features are products of existing base features, computed at feature-engineering time.

### Results

#### Test-set AUC-ROC comparison

| Model | A1 baseline (9 feat) | B2 (11 feat) | Delta |
|-------|---------------------|--------------|-------|
| Logistic Regression | 0.6799 | 0.6801 | +0.000 |
| Random Forest | **0.7403** | **0.7539** | **+0.014** |
| XGBoost | 0.7208 | 0.7170 | −0.004 |
| **Best** | **0.7403 (RF)** | **0.7539 (RF)** | **+0.014** |

#### Test-set classification metrics (B2)

| Model | Precision | Recall | F1 |
|-------|-----------|--------|-----|
| LR | 0.013 | 0.645 | 0.025 |
| RF | 0.067 | 0.194 | 0.099 |
| XGB | 0.000 | 0.000 | 0.000 |

#### Tier achieved

- Best model: Random Forest, AUC = 0.7539 → **Target tier** (≥0.70)
- Overall pass: ✓

### Analysis

**B2 is beneficial.** The interaction features provide a modest but consistent improvement for the Random Forest model.

Key observations:

1. **RF gains +1.4% AUC** — the explicit interaction terms reduce the tree depth needed to capture combined signals. RF now picks up `word_count_x_hour` as a readily available split candidate rather than needing to discover it through cascading splits on `word_count` then `hour_of_day`.

2. **LR unchanged** — expected. Linear models can't exploit multiplicative interactions without polynomial features, and L1 regularisation likely zeroed the interaction coefficients since they're correlated with their component features.

3. **XGBoost slightly dipped (−0.4%)** — likely noise given only 31 test positives. XGBoost's internal boosting naturally discovers interactions through sequential tree building, so the explicit features add little new information and marginally increase the search space.

4. **RF precision improved** (0.053 → 0.067) and confusion matrix shows fewer false positives (90 → 84) — the interaction features help RF be slightly more discriminating.

### Comparison with B1

| Experiment | Change | Best AUC | Delta from A1 |
|-----------|--------|----------|---------------|
| A1 (baseline) | 9 features | 0.7403 | — |
| B1 (drop weak) | 7 features | 0.6633 | −0.077 |
| **B2 (add interactions)** | **11 features** | **0.7539** | **+0.014** |

This confirms the lesson from B1: for tree models, more features (even with weak marginal signal) are better than fewer. Adding information helps; removing it hurts.

## B2b Experiment: Add more interaction features

### Rationale

Since B2 showed that explicit interactions help RF, test whether additional interaction terms can push AUC further. Two candidates with strong domain logic:

1. **`sentiment_x_word_count`** = `sentiment_score × word_count`
   - Hypothesis: emotional long posts (high-sentiment DD/hype with substantial content) are stronger surge indicators than short neutral posts
   - Sentiment alone is weak (AUC 0.47 univariate) but conditional on high word_count may carry signal

2. **`accel_x_hour`** = `ticker_post_acceleration × hour_of_day`
   - Hypothesis: posting momentum during market-relevant hours (pre-market 6–9, after-hours 16–20) is more predictive than acceleration at off-hours (e.g., 3am)

### Implementation

Added 2 more interaction features to `FEATURE_COLUMNS` (13 total). Same labelled dataset, no relabelling needed.

### Results

#### Test-set AUC-ROC comparison

| Model | A1 (9 feat) | B2 (11 feat) | B2b (13 feat) | B2b vs B2 |
|-------|-------------|--------------|----------------|-----------|
| Logistic Regression | 0.6799 | 0.6801 | 0.6818 | +0.002 |
| Random Forest | **0.7403** | **0.7539** | 0.7115 | **−0.042** |
| XGBoost | 0.7208 | 0.7170 | **0.7324** | +0.015 |
| **Best** | **0.7403 (RF)** | **0.7539 (RF)** | **0.7324 (XGB)** | **−0.022** |

#### Test-set classification metrics (B2b)

| Model | Precision | Recall | F1 |
|-------|-----------|--------|-----|
| LR | 0.013 | 0.645 | 0.025 |
| RF | 0.021 | 0.484 | 0.041 |
| XGB | 0.000 | 0.000 | 0.000 |

#### Tier achieved

- Best model: XGBoost, AUC = 0.7324 → Target tier (≥0.70)
- Overall pass: ✓ (but worse than B2)

### Analysis

**B2b is harmful.** The two extra interaction features hurt RF significantly and the overall best AUC dropped.

Key observations:

1. **RF degraded badly (−4.2%)** — the additional features created noisy split candidates that diluted the strong B2 signals. With 36 hyperparameter configs searched over only 31 test positives, RF likely overfit to the new features during CV and selected a worse configuration.

2. **XGBoost improved (+1.5%)** — XGB's sequential boosting and L2 regularisation handles extra features better than RF's random subspace sampling. But it still doesn't beat B2's RF result.

3. **LR unchanged** — as expected, L1 regularisation zeroes out the extra features.

4. **RF's confusion matrix tells the story** — FP jumped from 84 (B2) to 684 (B2b), meaning the extra features made RF far less discriminating. The model became trigger-happy.

### Why B2b failed where B2 succeeded

- **Diminishing returns**: RF already captured `sentiment × word_count` and `acceleration × hour` interactions implicitly through multi-level splits in B2. Making them explicit just added noise.
- **Feature space pollution**: more features = more candidate splits per tree node = higher chance of selecting a noisy split, especially with limited positive samples (667 train surges).
- **The "more features = better" rule has limits**: B1 showed removing features hurts, but B2b shows adding *redundant* features also hurts. The sweet spot is features that provide genuinely new information.

### Experiment log entry

- `2026-07-13_06-24` — B2b training: best AUC 0.7324 (XGB), target tier

## Decision (B2b)

**Revert B2b.** Restore features.py to the 11-feature B2 configuration. The B2 result (RF AUC = 0.7539) remains our best.

## B3 Experiment: Lower surge threshold τ from 1.5 to 1.0

### Rationale

With τ=1.5, only 31 test surges exist — too few for statistically reliable precision/recall/F1. The threshold sensitivity sweep showed τ=1.0 gives a higher surge rate while maintaining meaningful class separation. More test positives means:
1. Reliable evaluation metrics (less noise from individual TP/FP)
2. Better CV signal during hyperparameter search (more positives per fold)
3. A more practically useful detector (catches surges earlier, at moderate growth levels)

### Implementation

Relabelled the full dataset with `--threshold-tau 1.0`. This required running the labelling pipeline (surge labels are defined by τ) followed by retraining. Features unchanged at 11 (B2 configuration).

- Labelling: `python src/run_labeling.py --threshold-tau 1.0`
- Training: `python src/run_training.py --threshold-tau 1.0`

### Data distribution change

| Metric | τ=1.5 (B2) | τ=1.0 (B3) | Change |
|--------|-----------|-----------|--------|
| Total surges | 698 (2.8%) | 2,042 (8.2%) | 3× more |
| Train surges | 667 | 1,898 | 3× more |
| **Test surges** | **31** | **144** | **4.6× more** |
| Imbalance ratio (test) | 105:1 | 22:1 | Much healthier |
| Imbalance ratio (train) | 31:1 | 10:1 | Much healthier |

### Results

#### Test-set AUC-ROC comparison

| Model | B2 (τ=1.5, 11 feat) | B3 (τ=1.0, 11 feat) | Delta |
|-------|---------------------|---------------------|-------|
| Logistic Regression | 0.6801 | 0.6173 | −0.063 |
| Random Forest | **0.7539** | **0.7108** | −0.043 |
| XGBoost | 0.7170 | 0.7095 | −0.008 |
| **Best** | **0.7539 (RF)** | **0.7108 (RF)** | **−0.043** |

#### Test-set classification metrics (B3)

| Model | Precision | Recall | F1 |
|-------|-----------|--------|-----|
| LR | 0.054 | 0.674 | 0.100 |
| RF | 0.092 | 0.576 | 0.159 |
| XGB | 0.333 | 0.021 | 0.039 |

#### Tier achieved

- Best model: Random Forest, AUC = 0.7108 → **Target tier** (≥0.70)
- Overall pass: ✓

### Analysis

**AUC dropped, but this is expected — B3 defines a harder task, not a worse model.**

Key observations:

1. **The classification problem is harder at τ=1.0.** With a lower threshold, "surge" now includes milder growth events (ratio ≥1.0 vs ≥1.5). These borderline cases are inherently more ambiguous — the feature signal separating them from non-surges is weaker.

2. **Evaluation metrics are now statistically meaningful.** 144 test positives (vs 31) means precision/recall/F1 are no longer dominated by single-digit TP counts. RF's recall=0.576 and precision=0.092 are interpretable operating characteristics.

3. **RF and XGB converge** (0.7108 vs 0.7095) — at the easier class separation (τ=1.5), RF benefited more from the interaction features. With τ=1.0 and a fuzzier boundary, both tree models perform similarly.

4. **LR struggles most** (0.6173) — the linear decision boundary fails to separate the more ambiguous borderline surges. Tree models handle the non-linear boundary better.

5. **F1 scores are much more meaningful:** RF achieves F1=0.159 (vs the near-zero F1 values at τ=1.5 where XGB predicted no surges at all). The model is actually making useful predictions.

### B2 vs B3: not directly comparable

These experiments define **different tasks**:
- B2 (τ=1.5): "Detect strong surges" — rare events (2.8%), high AUC but unreliable evaluation
- B3 (τ=1.0): "Detect moderate+ surges" — more common (8.2%), lower AUC but reliable evaluation

AUC comparison across different τ is misleading because the positive class definition changed. The correct interpretation is:

| Configuration | Question answered | Reliability |
|---------------|------------------|-------------|
| τ=1.5 | "Will this ticker see >50% growth in posting?" | Low (31 test events) |
| τ=1.0 | "Will this ticker see any growth in posting?" | High (144 test events) |
