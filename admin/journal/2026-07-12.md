## B1 Experiment: Drop weak features

### Rationale

The improvement plan identified two features with weak single-feature AUCs:
- `sentiment_score`: AUC = 0.47 (below random)
- `ticker_post_rate_24h`: AUC = 0.56 (barely above random)

Hypothesis: removing noise features should reduce overfitting and improve generalisation.

### Implementation

Quick route — edited `FEATURE_COLUMNS` in `src/surge_pipeline/features.py` to remove the two features. No relabelling needed (features are model inputs, not label definitions). Training ran on the same `2026-07-12_10-02_labelled_dataset.csv`.

### Analysis

**B1 is harmful.** Dropping the two features caused significant AUC regression across all three models, especially RF (−0.085) and XGB (−0.063).

Key insight: weak single-feature AUC does not mean the feature hurts multi-feature models. Tree-based models (RF, XGBoost) can exploit features with weak marginal signal through:
- **Interaction effects**: `sentiment_score` may be informative *conditional* on other features (e.g., high sentiment + high word_count + peak hour)
- **Split refinement**: even a noisy feature can reduce Gini impurity in deeper tree nodes where the population is already filtered

The LR with elasticnet already handles this correctly — it selected l1_ratio=1.0 (pure L1) which zeros out truly useless coefficients automatically. Removing features manually just reduces the information available to tree models.

## Decision

**Revert B1.** Restore `sentiment_score` and `ticker_post_rate_24h` to `FEATURE_COLUMNS`. The A1 configuration with all 9 features remains the best result.

## Lessons learned

1. Single-feature AUC is a poor predictor of multi-feature importance for tree models
2. L1 regularisation already performs automatic feature selection for linear models — manual removal is redundant
3. For RF/XGB, feature importance (permutation or Gini) would be a better signal than univariate AUC for deciding which features to drop
